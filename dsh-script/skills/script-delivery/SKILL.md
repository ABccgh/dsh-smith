# 工序与交付契约

## 〇、先读这一节：工作台现在**没有在拍的短剧**

> **毕业照 / 金枝 / 家规三个剧本已取消并完全删除**（git `0ace833`，D-69，`D:\AIVideo\DECISIONS.md:3011`）。
> `products\` 下现在只剩 `image-to-video`（自用单件，非营收）与 `travel-promo`（两份参考件，订单已取消）。
> **它们都不是剧本。**

盘上**唯一完整的一部剧**是测试夹具 `D:\AIVideo\tools\_fixtures\series-min\`（12 集的功能表、4 件圣经）。
它的用途是**回归测试**，不是内容。

⚠️ **任何技能、任何记忆层里把这三个名字当成在拍的项目，都是过期信息**，读到就当缺陷报出来。
本技能描述的是**一部新剧**要走的工序。

## 一、这条流水线：**一道人工闸门，一个回环**

```
① 编剧（智能体）        products\<剧名>\script\可导入-<剧名>-全N集.txt
        ↓
② 平台评估（用户做）     有戏AI：登录 → 粘贴剧本 → 生成剧集 → 立即发起评估
        ↓
③ 读数回填（智能体）     products\<剧名>\评估报告-回填.json 的 readings[]
        ↓
④ 用户说「满意」或「不满意」
        ↓
⑤ 按读数改稿（智能体）    只改正文 → 回到 ①，并要求用户**再点一次评估**
```

**② 是硬闸门，不是复核。** 「停下来等人」由用户执行、用户判断，
而且**平台这一步你驱动不了** —— 有戏AI 没有 CLI、没有公开 API，`D:\AIVideo` 里也没有任何凭证
（实测：全树递归搜 `.env*` / `*token*` / `*cookie*` / `*credential*` / `*secret*` → **0 个文件**）。
逐条能力边界见 `youxi-platform` 技能。

**④ 之后回到 ①：这是一个回环，不是单向流水线。** 本项目实测跑过 **6 次读数、5 次改写**
（`D:\AIVideo\PROJECT.md:157`）。所以「交付」不是终点，「读数回来 → 改 → 再交付」才是常态。

### 你的回合在哪里结束（这张表是本技能的核心）

| 工序 | 谁做 | 你的回合 |
| --- | --- | --- |
| ① 写正文并交付 `可导入-<剧名>-全N集.txt` | 你 | **交付完就结束回合** |
| ② 平台评估 | **用户** | 等 |
| ③ 读数回填 | 你 | **回填完再结束一次回合** |
| ④ 说「满意 / 不满意」 | **用户** | 等 |
| ⑤ 按读数改稿 | 你 | ④ 之后才开工；改完**再交付、再请用户评估** |

**交付之后不要再顺手做下一阶段的事。** 结束回合时把三件事说清：

1. **你交付了什么** —— 绝对路径、字数读数、分集标记样式、你跑过的检查结论。
2. **用户要做什么** —— 登录有戏AI → 粘贴正文 → 生成剧集 → 点「立即发起评估」。
3. **你在等什么** —— 一份评估读数（总分、等级、五维分、诊断文字，有诊断就带上）。

**等待不要用一轮轮追问占住会话**：把这个等待**写进交付说明并结束回合**。
它本来就跨会话 —— 用户下次打开会话时才会读它，而每一轮追问的代价是你每一轮都在重放同一个等待。
（这条纪律原先靠一个持久邮箱工具承载；那个工具已于 2026-09-24 移除，纪律本身不变。
**也不要用 `ask_user_question` 去问它** —— 那是阻塞式的，会把一次交付变成一次打断。）

> **绝不在用户确认之前按自己的判断改稿。** 本地契约检查的通过是**手艺**判据，平台的评级是**内容**判决。
> 本项目已经为此付过学费：一份**本地断言全绿**的剧本，平台判了 **D 55.7**（D-17/D-18）。
> 「本地过了」不是「可以继续」的理由。
>
> **还有一个静默的陷阱：平台不会自动重评。** 改完不提醒用户再点一次，读数永远停在旧的那次，
> **而你以为流程在往前走**。这是本回环里最容易犯又最难发现的一种错。

## 二、① 写作阶段：交付什么，交付成什么样

**交付物**：`products\<剧名>\script\可导入-<剧名>-全N集.txt` —— **平台真正导入的那一份**。
（同目录还有单集版 `可导入-第NN集.txt`，那是写与改稿时的依据。）

由 `tools\episode-build.mjs` 从 `episodes\第NN集.json` 这份源重拼，**不要手写这个 txt**：

```powershell
node D:\AIVideo\tools\episode-build.mjs --series D:\AIVideo\products\<剧名> --all --script
```

### 四条会决定评级/被拒的硬约束

| 约束 | 值 | 谁判 |
| --- | --- | --- |
| **单集字数** | 目标 **1 600–1 900**；本项目自己声明的下限（缺省 1450）；**平台硬上限 2 000** | 检查器（逐集）＋平台（超了直接拒） |
| **全集字数** | ≤ **100 000** | 平台（「剧本支持10万字以内」） |
| **分集标记** | 全用 `第N集`，或全用 `第N章`；**不得混用**；中文数字与阿拉伯数字也不得混用 | 检查器＋平台（混用即分不了集） |
| **四类行** | 每一行必须归入 场景行／人物行／△ 动作行／台词行 | 检查器 |

**这四条的确切判据、行号与实测读数在 `script-rules` 技能里 —— 那份是权威，这份不是。**
这里只给形状与理由。

> **字数是内容判据，不只是格式判据。** 本文件记录的那两次实测读数：全 12 集 **2 526 字**（每集约 210 字）→ **D 55.7**；
> 同一故事改写后全 12 集 **20 554 字**（每集 1 630–1 895 字）→ **A 82.6**，五维全部上升。
> 「薄」在这里不是风格问题，是**扣分项**。写完必须**读回文件数出真实字数**，不是估计。

平台原文（两条真的会拦你的规则，其余都是我们自己的纪律）：

> 请导入剧本，将为你自动分集（文本请用"第n章/集"分割）
> 剧本支持10万字以内，长剧本需要分集，**每一集必需控制在2000字以内**
> **不能混合使用**，比如在同一个剧本中，同时使用：第1章， 第2集 ，这样是不能分集的

## 三、闸门：**四态**，不是三态

**首选路径是 `duanju_gate` 工具，不是手敲 node。**

```text
duanju_gate { series: "D:\AIVideo\products\<剧名>", range: "script-only" }
```

**`range` 在本 preset 里只有一个取值。** 旧的 `episode` / `series` / `cross-episode` 三个范围
**全部以分镜表存在为前置**（无分镜表即早退，E1–E20 或 E21–E31 一条都不跑），
而分镜表已移出本 preset —— 那三个范围在这里没有输入可判。
实测佐证与「怎么现读工具表确认」写在 `script-tools` 第一节。

回退（工具不可用时）：`node D:\AIVideo\tools\script-only-check.mjs --series <剧目录>`。

| 结论 | 含义 | 是不是通过 |
| --- | --- | --- |
| `PASS` | 判完了，通过 | **是**（仅对它判过的那几条） |
| `FAIL` | 判完了，确认不通过 | 否 |
| **`UNAVAILABLE`** | **判不了**（缺文件 / 缺目录） | **不是** |
| **`CRASHED`** | **脚本崩了**，或参数用错（`USAGE` 变体同版式） | **不是** |

### 为什么会有第四态：退出码 `4` 不可达，而且崩溃与用法错都是 `1`

闸门自己的文档写着「退出码 `0` 全通过 / `1` 用法或输入错 / `2` 有 `FAIL` / `3` 有 `UNAVAILABLE` /
`4` 运行期异常」（`script-gate.mjs:46` 的头注释与 HELP `:441`），**而 `4` 在代码里不可达** ——
全 2 859 行里 `exit(4)` / `return 4` / `exitCode = 4` 的出现次数是 **0**（实测）：

- `main()` 定义在 `:1719`，只返回 `0/1/2/3`：`:1726` `:1734` `:1745` 用法/输入错 → 1，`:1730` 帮助 → 0，
  `:2850` 有 `FAIL` → 2，`:2851` 有 `UNAVAILABLE` → 3，`:2852` → 0，`:2853` 结束。
- 唯一的 `try/catch` 包的是 `parseArgs`（`:1722-1723`），所以**任何别的抛出都是未捕获异常**，Node 给 **`1`**。

⇒ **崩溃与用法错误在退出码上是同一个数。** 这正是 `duanju_gate` 加第四态的理由：
它**不读退出码下结论**，判据是 **stdout 能不能解析成判据行**，加上 **stderr 里有没有「用法错误」**
（插件侧：`D:\dsh-duanju-script\lib\rules.mjs:139-153`，含文本方言那一条）。
看到 `1` 时先分清是**参数用错**还是**脚本崩了**，不要用退出码下结论。

> **这条引用要现读。** 旧版本的本文件把退出码那一行记在 `script-gate.mjs:45` —— **今天它在 `:46`**
> （`:45` 是一个空的注释行）；`process.exitCode = main()` 在 `:2859`。文件长长了，
> **没有任何检查因此变红**。引用行号时先确认它还在那儿。

### 看三件事，不是看退出码

① 有没有 `FAIL`；② 有没有 `UNAVAILABLE`／`CRASHED`（逐条处理，缺素材就补素材，**不许当绿灯跳过**）；
③ **`findings` 要整体读** —— 它是 list，不是 map；同一个 code 可以出现多次，
**按 code 取首条会静默丢掉结论**。

**两条必须原样带上的话** —— 工具每次都会印（`rules.mjs:221-222`）：

> `?` 是**跑不了**（缺文件/缺目录），与 `✗` 一样非零退出，**绝不是通过**。
> 某个 code 没出现在上面，**不等于它过了**：`E5`/`E6` 在圣经读不到时会**故意什么都不发**，由 `E0-输入完整性` 代言。

> **没出现的 code，不等于它过了。** 所以「我在报告里没看到某一条」**不构成任何结论** ——
> 空白要被读成空白，不是读成绿灯。

> **绝不要把 `duanju_gate` 报成「闸门过了」，当它返回的是 `UNAVAILABLE` 或 `CRASHED`。**
> 本工作台为这条付过学费：**「读不到」必须在输出上与「没有问题」不同**，否则下游会把空结果集当成通过。

## 四、判据的边界：本 preset 的闸门只判正文那六类

`range: 'script-only'` 跑的是 `script-only-check.mjs`，它判的是：
**集标记、四类行、字数区间、场景台词比、`story.json` 一致、禁止项**（六类，逐条见 `script-rules`）。

**它判不了「故事好不好」与「卡点强不强」** —— 那两样只有人读。它每次运行都会自己印这句话：

> ⚠️ 它判不了：集数与时长是否合平台口味、卡点强不强、故事好不好看。
> **它通过 ≠ 平台会通过**（D-17/D-18）。唯一有效的「好不好」检查是人读。

**它也不判读数自洽** —— 那一条（旧口径叫 `E19b`，属闸门的 `series` 范围）现在由
**`duanju_recall`** 承担（`rules.mjs:633-710`），见第五节。

## 五、③ 读数回来之后：四件事

1. **追加**一条到 `products\<剧名>\评估报告-回填.json` 的 `readings[]`（**不改旧条目**），
   并把顶层的便捷副本同步成最新那次。
2. 跑 **`duanju_recall`**，把它的读数自洽结论写出来。
   **追加后再跑** —— 先跑会让它判的是上一次的状态，那次结论是假的。
   ⚠️ 它**只证明那个文件自洽**（顶层副本与末条一致、`grade` 与总分映射一致、五维 id 顺序与均分 ×10 相符），
   **抓的是转述错字，抓不出整份报告读错**。这句话要跟着读数一起出现，别让它看起来像一次实测。
3. **报出与上一次读数的差**（每一项维度的升降，以及总分与等级的移动）。没有上一次就写「这是首次读数」。
4. **标注证据等级**：读数来自用户在会话里的**转述**，本机没有该平台的登录态 ——
   读不到报告文件，也读不到截图。写「本次读数为用户转述」，能拿到导出件或截图时补进 `_原报告来源`。

**⑤ 改稿阶段：只改正文**，改完**明确提醒用户再点一次评估**（平台不会自动重评）。

**不允许**：

- **预测评级。**
- 把本地检查的 `PASS` 当成用户的「满意」。
- 平台只给分不给诊断时自己编一份诊断 —— 如实说「这一次没有诊断文字，所以『还差在哪』没有权威答案」。
- 把两个不同评估方的数字相减（量纲不同，任何两个相减都是错的 —— `script-review` 第八节）。

## 六、工具给交付契约的三件事（首选路径）

`duanju_gate` / `duanju_recall` / `duanju_checkpoint` 由宿主平面的 `dsh-duanju-script` 插件注册，
**每个会话都能看见**（也就是说，它们的出现**不**证明你在本 preset 的会话里）。**`duanju_*` 是首选，`node` 脚本是回退。**

| 工具 | 在交付契约里的位置 |
| --- | --- |
| **`duanju_recall`** | **声称任何状态之前先跑它。** 只读投影：`story.json` 的集数与时长、`manifest.json` 的平台模式、圣经四件、`script\` 命名与字数、最新一次读数**带差值**。它的读数是**自洽性**检查，且它**每次都印那句警告**：抓得出转写错误，**抓不出整份报告读错**。 |
| **`duanju_checkpoint`** | 把投影渲染进 `products\<剧名>\项目总览.md` 的**受管区块**。**先跑 `dryRun: true`** 看它要写什么；不带 `dryRun` 就是一次写。受管区块的纪律（只改两个标记之间的字节）见 `drama-project-memory` 技能。 |
| **`duanju_gate`** | 判据本身（第三节）。**四态，不看退出码。** |

> **精确参数、输出形状与四态语义，见 `script-tools` 技能**（这张表只讲交付契约要用的三个）。
> 一条边界值得在这里先记住：**这些工具没有任何一条检查被重新实现** ——
> `duanju_gate` 的全部结论来自脚本，它自己的判断只有「分类成哪一态」和「渲染」。
> 所以**工具的可信度等于它所转调的那份脚本的可信度**，脚本漏判的它同样漏判。

## 七、本 preset 到此为止

**平台读正文，不读分镜。** 你交付的那一份 txt 就是平台评估的对象；
分镜表与它的平台导入模板**不在本 preset 的范围内**，也不在你的工序里 ——
没有「等读数回来之后再做下一步产物」这件事了，流水线在 ⑤ 之后回到 ①。

**平台侧的一切（生成剧集、发起评估、导出、投稿）都是用户在网页上做的。**
你没有这个能力，也不要声称有（逐条见 `youxi-platform` 技能第二节）。

## 八、三条已实测的失败模式，不要重犯

1. **薄**：正文写成每集两百字，结构断言全绿，平台判 D。字数是内容判据。
2. **两个真相**：手改了交付用的 `script\*.txt`，而源 `episodes\第NN集.json` 没改 ——
   下一个跑生成器的人会把它覆盖掉，**而在覆盖之前没有任何东西会报错**。
   两者必须**同源**（都由 `episode-build.mjs` 从那份 JSON 生成）。
3. **把「跑不了」当「通过」**：工具报 `UNAVAILABLE`（或 `CRASHED`）时跳过，然后在平台侧付学费。

> 第 3 条的变体值得单独记住：**退出码 `1` 分不开「参数用错」与「脚本崩了」**，
> 所以**先看 stdout 有没有判据行**。
> 还有一个更反直觉的变体（本机实测，见 `script-tools` 第二节）：**剧目录里没有 `story.json` 时，
> 那份运行退出码是 3，而工具会把它报成 `CRASHED`** —— 标签是 `CRASHED`，原因却是缺一个文件。

## 九、开工前的一分钟自检

- [ ] 我知道这一步的**交付物**是哪个绝对路径的文件
- [ ] 我知道这一步**要不要过人工闸门**（要过 → 我交付完就停，**不顺手做下一阶段的事**）
- [ ] 我把「等用户读数」写进了**交付说明**并结束了回合，而不是用追问占住会话
      （持久邮箱工具已于 2026-09-24 移除；`ask_user_question` 是阻塞式的，不用它承载跨会话等待）
- [ ] 我跑过 `duanju_gate`（`range: 'script-only'`），并**引用了它的原文**（含「跑不了 ≠ 通过」那句）
- [ ] 我读的是 `findings` **整个列表**，不是每个 code 的首条
- [ ] 我读过 `bible\*.json`，不是凭记忆写角色/道具名
- [ ] 回填读数时我是**追加**的，跑自洽检查在追加**之后**
- [ ] 改稿之后我**明确提醒过用户再点一次评估**（平台不会自动重评）
- [ ] 我报的每个数字都有出处；没有实测数字的地方我说「未测量」
