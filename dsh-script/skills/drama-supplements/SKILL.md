# 平台规则的缺口与冲突：怎么处理

## 〇、一句话原则

**没有出处的规则不许写下来；没测过的数字不许算出来。**

本工作台的记忆层与技能里**不许冻结平台的规则**（`drama-project-memory` 第二节的规则二）——
平台的评分口径、评级映射、闸门条件都会变，冻结一份进去，下一次平台改动就把它变成谎话，
**而且没有任何检查会因此变红**。它们以**引用**的形式旅行：带出处（文件:行 / 平台产物 / 读的时间）。

这份技能处理的是这句话背后的两种具体情形：**查不到**，和**两份来源互相矛盾**。

## 一、四种状态的严格区分

对一条平台规则，你只可能处在四种状态之一。**把它们混在一起是本工作台最贵的一类错。**

| 状态 | 你该写什么 | 你**不许**写什么 |
| --- | --- | --- |
| **读到了** | 逐字原文 ＋ 出处（文件:行 / 平台产物 / 平台页面 ＋ 读的时间） | 不许转述成自己的话而不留原文 |
| **读不到** | 「未测量」＋ **说清为什么读不到**（没有登录态？没有账号？界面改版了？） | 不许用「大概是」「一般来说」补一个值 |
| **两份来源矛盾** | 两份都写下来，各自带出处，标出冲突 | 不许替平台挑一个（除非有一份来源是**代码**，见第三节路径 A） |
| **来源是用户转述** | 「本次读数为用户转述」＋ 转述的时间与场合 | 不许升格成实测 |

**为什么这条不是文风问题。** 本工作台付过学费：一份**本地断言全绿**的剧本，平台判了 **D 55.7**
（D-17/D-18；两次读数对照见 `script-delivery` 第二节）。当时的错误不是「不知道平台怎么评分」，
而是**把自己会的东西当成了平台会认的东西**。
「未测量」这四个字是**可行动的**：它告诉下一个会话「这里需要一次实测」，而一个编出来的阈值
会告诉它「这里已经测过了」—— 后者更贵，因为它让人不再去测。

## 二、一条规则有四种来源，从高到低

**高优先级压过低优先级，但高优先级也要说明自己是哪一层。**

1. **平台的运行时产物**（前端 bundle、接口响应、页面原文）。这是平台**自己**的字节。
   读的时候记下「哪个产物、哪一段、什么时候」，因为前端会随发布变化。
2. **平台自己发布或被平台接受的官方文件**（例如平台创建页给出的示例格式）。比一句文档更硬。
3. **用户提供的导出件／截图**（评估报告的 zip、PDF、截图）。**次级**：它是平台对**某一次运行**的
   输出，不是平台的规则；而且要标明它测的是**哪一版**正文 —— 本项目有过三个版本的三次读数
   被混着比的事故（见 `script-review` 第七节第二问）。
4. **用户的口头转述**。可用，但必须标注，并且它**只能被当成读数，不能被当成规则**。
5. **本工作台的技能与记忆层**。**最低**，而且**只应该引用前四层**。
   技能里出现一个平台数字而没有出处，那个数字应该被删掉或补上出处。

> 一条推论：**如果一条平台规则只在本工作台的文档里存在，它就已经失去了权威。**
> 要么去第一层重读一次，要么标成未测量。

⚠️ 本工作台的读数**绝大多数是第 4 层** —— 本机没有有戏AI 的登录态，读不到报告文件也读不到截图
（`drama-project-memory` 第五节）。所以引用任何一条平台分数时，「它是转述」这句话要跟着走。

## 三、矛盾出现了怎么办：三条裁定路径

**路径 A —— 有一份来源是代码，代码赢。**
本工作台的脚本是**我们自己的**代码，不是平台的规则，所以它对**我们自己的契约**有绝对权威。
正文侧最典型的一例：平台原文写「文本请用"第n章/集"分割」，看起来两种写法都收；
而检查器的集号连续性、集数断言只认阿拉伯数字的 `第N集`（`script-only-check.mjs:67`），
**全用中文数字的稿子会被判「标记出 0 集」**（实测读数与两个样本见 `script-rules` 第一节）。
⇒ **代码的认法赢，且这是实测的。**

**代码赢的适用范围要划清**：它裁的是「我们的检查到底怎么判」这种问题。
它**裁不了**「平台到底会不会接受这份正文」—— 那是平台行为，不是文件属性。
那需要用户在网页上点一次「立即发起评估」（`youxi-platform` 第一节）。

**路径 B —— 有一件工具能当场读出来，读它。**
第四节每一条冲突都配了一个裁定动作。**能读的就不要讨论**：用 `duanju_recall` 拿一部剧的
当前状态，或**直接去读那部剧自己的 `story.json` 与那份正文**，而不是引这份技能里的数字。

**路径 C —— 两边都是平台口径且读不到 → 报给用户，不要自己裁。**
平台侧的规则冲突、以及**项目侧的取舍**（例如 `paywall` 字段与 `monetization.freeEpisodes`
不一致）都属于这一类。**报出来的形态**：两份读数并排、各自出处、你的影响分析、
以及「这需要你定，因为它改的是产品而不是文件」。用 `ask_user_question`，
或者放进 `inbox_add`（如果这个答案跨越整个回合）。

## 五、写下一个数字之前的四问

1. **它的出处是这四层里的哪一层？**（平台产物 / 平台文件 / 用户的导出件 / 用户转述）
   说不出层，就别说出来。
2. **它是一次读数还是一条规则？**（读数属于某一次运行，规则属于平台 —— 两者混淆会变成谎话）
3. **它测的是哪一版？** 本工作台有过三个版本的三次读数被混着比的事故。
4. **它有没有可能已经被推翻？** 如果是老读数，先看记忆层里有没有更新的那条；
   回填文件的自洽校验会告诉你转述有没有抄错（`script-review` 第三节）。

四问过不去 → 写「**未测量**」，并写清**要拿什么才能测**（一次登录、一次导出、一次页面读数）。

## 六、自查清单

- [ ] 我引用的每条平台规则都带**出处**（文件:行 / 平台产物 / 平台页面 ＋ 时间）？
- [ ] 我说「未测量」的地方，有没有说清**为什么**读不到、以及**什么能测出它**？
- [ ] 两处来源矛盾时，我是**并排列出**了两份读数，还是替平台挑了一个？
- [ ] 有一个来源是**代码**时，我让代码赢了吗？（字数下限、集标记认法、禁止项边界）
- [ ] 两边都是平台口径时，我**报给用户**了吗，还是自己裁了？
- [ ] 我有没有把一个**读数**当成一条**规则**写进技能或记忆层？
- [ ] 我有没有把两个不同评估方的数字相减？（**不许**）
- [ ] 我报的每个数字，都能指出它是哪一次实测、哪一行吗？
