# 正文的机器契约

这份技能只讲**机器真的会判**的东西。判据的出处是 `D:\AIVideo\tools\script-only-check.mjs`
（413 行），本机实测读数标了「实测」，其余标了行号 —— **引用任何一个阈值之前，先回去读那一行**。

> **判据的权威不是这份技能，也不是那个文件。** `script-only-check.mjs` 自己的文件头写着
> 「口径出处（**唯一权威是 script-gate.mjs，不是本文件**）」（`:24`），并把每一条判据映射到
> `script-gate.mjs` 的行号（`:25-33`）。所以链条是：**`script-gate.mjs` → `script-only-check.mjs` → 这份技能**。
> **在本 preset 里你不需要跑 `script-gate.mjs`** —— 它靠分镜表才跑得动，而分镜表不在本 preset 的范围内。
> 这里提它，是因为**判据的原文在那里**：引用一条阈值时要知道自己在引谁的字节。
> 两份实现是手工同步的，多一份实现就多一个漂移面（`D:\dsh-duanju-script\lib\rules.mjs:96-98` 记着这句话）。
> 读到任何不一致，**代码赢**，并把不一致报出来。

## 〇、它判不了什么（每次运行都会自己印出来）

```
⚠️ 它判不了：集数与时长是否合平台口味、卡点强不强、故事好不好看。
   **它通过 ≠ 平台会通过**（D-17/D-18）。唯一有效的「好不好」检查是人读。
```
（`script-only-check.mjs:409-410`，逐字节）

**这句话要跟着任何一次「检查通过」一起出现。** 它通过只说明六类机械判据过了：
集标记、四类行、字数区间、场景台词比、`story.json` 一致、禁止项（`:406`）。

## 一、分集标记：三条统一规则，一条实测的陷阱

**规则一：`第N章` 与 `第N集` 不得混用。** 平台原文是「**不能混合使用**，比如在同一个剧本中，
同时使用：第1章， 第2集 ，这样是不能分集的」（引用自 `youxi-platform` 技能第三节）。
代码在 `:63`：`kwSet.has('章') && kwSet.has('集')` → 报「同时用了「第N章」与「第N集」」。

**规则二：中文数字与阿拉伯数字不得混用**（`:64`）。两种形式的行首标记分别匹配：
`:60` 的 `^[ \t]*第\s*[〇零一二两三四五六七八九十百]+\s*([集章])` 与 `:61` 的 `^[ \t]*第\s*[0-9]+\s*([集章])`。
两者都非空即报「全篇统一成一种」。

**规则三：冒号写法与裸写法不得混用**（`:99-103`）。`第N集：标题` 与 `第N集` 是两种写法
（代码里叫 `colon` / `bare`），`styles.size > 1` 即报错。这是 E28 的判据，与上面两条不是同一条。

⚠️ **实测（本机跑过，不是推断）——「全用中文数字」看起来合规，实际上是坏的。**
集号连续性与集数两项只看**阿拉伯数字＋`集`**：`marks` 的定义是
`^[ \t]*第\s*([0-9]+)\s*集[^\n]*$`（`:67`），**它不认中文数字，也不认 `章`**。
我拿一份对照样本测过：

| 样本（单集、其余逐字节相同） | 读数 | 退出码 |
| --- | --- | --- |
| `第1集：甲` | `集标记 1 个（声明 1）`，0 条问题，`✓ [PASS]` | 0 |
| `第一集：甲` | `集标记 0 个（声明 1）`，2 条 FAIL：`E9：整部导入版标记出 0 集，但 story.json 声明 1 集` ＋ `E28：正文里没有第1集` | 2 |

⇒ **实际可用的只有 `第N集`（阿拉伯数字）**。中文数字不会撞上「混用」那条，却会被集数断言与
逐集元数据比对一起判空，报出来的话还不是「数字形式不对」，而是「标记出 0 集」。

其余两条：集号必须从 1（或区间模式的起点）开始并连续（`:74-81`）；整部模式下
**标记数必须等于 `story.json` 的 `episodeCount`**（`:83-85`）。

## 二、四类行：正文里每一行都必须归入其中一类

`:121-137` 逐行判定，顺序是有意的：

| # | 类 | 判据 | 出处 |
| --- | --- | --- | --- |
| 1 | **场景行** | `^场\s*\d+`，且**必须以 `／内` 或 `／外` 结尾**（`/[／/]\s*(内|外)\s*$/`） | `:121`、`:126` |
| 2 | **人物行** | 场景行的**下一行**必须是 `^人物\s*[：:]` | `:129-132` |
| 3 | **动作行** | 以 `△` 开头 | `:134` |
| 4 | **台词行** | `^[^：:]{1,10}[：:]` —— 冒号前 1–10 个非冒号字符 | `:135` |

- **人物行只在「紧跟在场景行之后」这一个位置被判**（`:129`）。别处再出现人物行，会落到第 4 类或报错。
- 不属于四类之一的行报「这一行不属四类之一 ——「…」」（`:136`）。
- 每集至少要有一个场景行，否则报「一个场景行都没有」（`:139`）。
- 场景行末尾那条判据来自平台自己的示例格式 `场N　地点　时间／内`
  （`script-gate.mjs:1525-1526` 的报错原文引了它）。

## 三、字数：下限是**我们自己的**，上限才是平台原文

| 项 | 值 | 谁定的 | 出处 |
| --- | --- | --- | --- |
| 每集**下限** | `story.json` 顶层 `episodeCharsMin`，**缺省 1450** | **工作台自己** | `:106` |
| 每集**上限**（声明口径） | `story.json` 顶层 `episodeCharsMax`，**没有缺省** | 项目自己声明 | `:107`、`:143` |
| 每集**上限**（平台口径） | **2000**，按**段**算 | **平台原文** | `:38`、`:91-94` |
| 全集上限 | **100000** | **平台原文** | `:39`、`:95-96` |

**「1450 不是平台的规则」这句话有代码依据**，而且写着它的那一行就在权威文件里：
`script-gate.mjs:1645-1646` ——「1450 是本项目按平台 2000 字上限留出的余量定的目标下限，
**不是平台的规则**……写死在闸门里会让别的剧、以及闸门自己的夹具一起被误判」。

**2000 与 100000 是平台原文**：`script-gate.mjs:240` 是
`const PLATFORM_EPISODE_CHAR_LIMIT = 2000 // 官方原文：每一集必需控制在2000字以内`，
`:241` 是 `= 100000 // 官方原文：剧本支持10万字以内`。
（注意：`script-only-check.mjs:33` 的文件头把这两个常量记在 `:240`/`:241` —— 指的是
`script-gate.mjs` 的行号；它**自己**的这两个常量在 `:38`/`:39`。）

**2000 是拒收线，不是扣分线。** 平台原文是「每一集必需控制在2000字以内」。
本工作台早先的 `shotlist` 技能（**它的题材是分镜表，已随那份题材一起移出本 preset，不要去找它**）
把这句总结成「**超了是拒收，不是扣分**」—— 这个总结仍然成立，因为它就是平台原文的意思。

⚠️ **2000 那条是按「段」判的，不是按集号判的。** `:87-90` 用
`/^[ \t]*第\s*(?:[0-9]+|[〇零一二两三四五六七八九十百]+)\s*[集章].*$/m` 切段 ——
**两种数字形式、`集` 与 `章` 都在内** —— 然后逐段判长度（`:91-94`）。
报错里的编号是**段的序号**（`:93` 的 `第${i+1}段`），不是集号。所以文件头若有说明文字，
它会被算成第 1 段。

**下限从 `story.json` 读，这一点有实测的重量。** `products\毕业照` 交付的那 70 集，
`script-only-check --series` 报 **0 条契约问题 ＋ 0 条禁止项**，而每集只有 **744–897 字**
（`D:\AIVideo\PROJECT.md:385`）；同一份交付在更早一轮的读数是每集 **614–898 字**（`:205`）。
两者都低于缺省的 1450。
**推断**：那份 `story.json` 显式声明了一个远低于 1450 的 `episodeCharsMin` ——
**我没能验证它**，因为 `products\毕业照\` 已随项目删除，盘上读不到它的 `story.json`。
要证伪这条推断，只需对任何一份真实交付跑一次 `duanju_recall` 或读它的 `story.json`。

⇒ 所以「每集 1600–1900 字」是**实测出来的目标区**（见 `dramaturgy` 第六节与
`script-delivery` 第二节的两次读数对照），**不是机器判据**。机器判的是这份剧自己声明的区间。

## 四、台词比：按**场景**算，≥70%

`:110-112` 数两个量：`scenes` 与「至少有一句台词行的场景数」`scenesWithDial`；
`:149-152` 判 `scenesWithDial / scenes < 0.7` 即报「按场景算的台词占比 N%（x/y）低于 70%」。

三条必须一起记住：

1. **这个占比是整篇算一个数**（`:149`），不是逐集算的。
2. **单跑某一段低于 70%，不等于整部违规** —— 靠 `--episodes A-B` 模式时它会自己印这句警告
   （`:363-370`）。实测例子就在那几行注释里：**《毕业照》第 44 集单独跑是 33%，而整部 70 集是 89.5%**。
   不加这句，下一个人会去改一份本来没问题的正文。
3. **70% 这个数字的口径来源是分层的。** `script-only-check.mjs:30-31` 的文件头写着
   「场景台词比 ≥70%（**这一条是有戏AI 的口径，不是投稿平台的**）」；而平台如何计算这 70%
   （按场景／按镜头数／按时长）在 `script-gate.mjs` 的注释里被标注为**未验证**。
   引用这个阈值时，把这两层一起带上 —— 细节见 `drama-supplements`。

## 五、`story.json` ↔ 正文：三件必须对上的事

1. **`episodes[]` 必须存在**（`:163-164`：「story.json 没有 episodes 数组」）。
2. **每集的 `title` 必须与正文里 `第N集：标题` 的标题逐字相同**（`:169-171`），
   且**正文里与 `story.json` 里各自都不许重名**（`:159-161`、`:172-173`）。
3. **`cliffhanger` 必须有，且它的某个四字片段必须落在本集正文里**（`:175-183`）：
   把 `cliffhanger` 去掉标点（`:52` 的 `stripMeta`）后取所有长度 4 的子串，
   只要有一个出现在同样去掉标点的本集正文里就算过。找不到时报
   「卡点描述「…」在本集正文里找不到任何四字落点」。
   正文里根本没有这一集时报「正文里没有第N集」（`:178`）。
   卡点为空时单独报一条（`:177`）。

⚠️ **同一份元数据有两个字段，机器只判一个。** E28 判 `cliffhanger`，**不判 `hook3s`** ——
这是 `hook-audit.mjs` 文件头逐字记下的缺口（`D:\AIVideo\tools\hook-audit.mjs:13-14`），
它给了一个实测的例子：第 10 集的 `hook3s` 写着「手先摸上第三格的书背」而正文写的是
「第三格是空的」，「**一条元数据在自己最贵的地方说反了话，而 E28 看不见它**」。
⇒ **`hook3s` 要靠 `node D:\AIVideo\tools\hook-audit.mjs --series <剧目录>` 单独判**
（只读 `episodes\第NN集.json`，退出码 0 全有落点 / 2 有落点缺失 / 1 用法或输入错）。
它的判据与 E28 的卡点判据逐字相同（`hook-audit.mjs:59-68`），
**抓的是「这段元数据在说别集的事」，抓不出「它写得不精彩」**（`:25-27`）。

**四字判据是一条真实的契约约束**，不是夹具的怪癖：`cliffhanger` 去掉标点后必须 ≥4 字，
否则那条判据永远不可能满足（`:236-237` 的注释就是这么写的）。**`story.json` 也要守这一条。**

## 六、禁止项：只匹配「联系方式形状」的东西

`:205-221` 是完整的规则表，七条：

| 规则 | 正则 |
| --- | --- |
| 手机号 | `1[3-9]\d{9}` |
| 邮箱 | `[\w.+-]+@[\w-]+\.[\w.]+` |
| 微信号带账号 | `微信号\s*[:：]?\s*[A-Za-z0-9_-]{3,}` |
| 留微信 | `(加我?微信\|微信联系)` |
| QQ 号 | `(QQ\|qq)\s*[:：]\s*\d{4,}` |
| 水印/归属类字样 | `(编剧联系\|作者联系\|版权归\|版权所有\|严禁转载\|未经授权\|水印)` |
| 工作室签名 | `(某某)?(编剧\|作者)工作室` |

⚠️ **这条规则被收窄过一次，理由写在源码里（`:198-204`），要连着一起引用。**
第一版把**裸的「微信」「qq」**也写进去了，于是第 43 集里一句剧情动作**「是一张微信群的截图」**
被命中，写手只好把它改成「一条消息，下面跟着一长串回复」——
源码的原话是「**内容被一条本意是防联系方式、结果只认字面词的规则改掉了**」。
平台禁止的是**编剧的联系方式**，不是剧本里出现过一个聊天软件的名字。
所以现在**只匹配「联系方式形状」的东西**：号码、邮箱、带账号的微信号。

**这条收窄有反向断言做护栏，而且我实测它通过了**：自证里有一例
`△ 桌上是一部手机，屏幕上是一张微信群的截图。` 必须报 **0 条**（`:280-282`），
跑 `--selftest` 时它印的是 `✓ 剧情里的「微信群」**不得**被误报 → 0 条`。
⇒ **写剧情时不需要回避聊天软件的名字**；要回避的是号码、邮箱、带账号的微信号、
以及任何指向编剧本人或工作室的字样。

## 七、退出码，与两种运行模式

文件头的约定（`:18`）：**`0` 全通过 / `1` 用法或输入错 / `2` 有 FAIL / `3` 有 UNAVAILABLE**。

| 模式 | 读什么 | 判不了时 |
| --- | --- | --- |
| 整部（`--series <剧目录>`） | `script\可导入-第<剧名>-全N集.txt`，文件名匹配 `/^可导入-第[\s\S]+-全\d+集\.txt$/`（`:379`） | 一份都没有 → `? [UNAVAILABLE]` ＋ `汇总：不可读 1`，**退出 3**（`:381-387`）；**有两份及以上 → FAIL 退出 2**，因为它们里只有第一份会被读到，其余是**不会被读到的死文件**（`:388-392`） |
| 一段（`--episodes A-B`） | 逐集文件 `script\可导入-第NN集.txt`，且**每一份的第一行必须逐字是 `第N集：`**（`:326-327`） | 缺的集单独报 `? [UNAVAILABLE] 还缺 N 集的逐集文件`（`:331-336`）；**缺集不是失败，是「判不了」**（`:338-341` 的注释：把没写的集喂进去会产生 60 条幻影 FAIL，会把「还没写到」冒充成「写错了」） |

**两种模式都不落任何临时文件** —— 逐集模式直接读逐集文件，所以不可能制造
「`script\` 下有两份全N集文件」那个会让下游读错对象的陷阱（`:314-315`）。

⚠️ **有一个坑：退出码 3 的运行不一定被判成 `UNAVAILABLE`。**
`story.json` 读不到时，那份脚本走的是 `console.error('读不到 story.json —— 判不了（**不是通过**）')`
＋ `process.exit(3)`（`:308-309`）—— **stdout 一个字节都没有**。
而 `duanju_gate` 的分类器判「这次跑没跑」靠的是 stdout 里有没有判据行或 `汇总：` 行
（`D:\dsh-duanju-script\lib\rules.mjs:140`），拿不到就当崩溃或用法错。
**我实测过这条路径**：stdout 0 字节、stderr 61 字节、退出码 3，
把这份读数喂给插件自己的分类器，它返回 **`CRASHED`**，理由逐字是
「没有拿到任何判据行、也没有汇总行 ⇒ 按**崩溃**记」。
⇒ 净效果仍然是**不是通过**（`UNAVAILABLE` 与 `CRASHED` 都不是），但**标签会是 `CRASHED`**。
看到 `CRASHED` 时先找「剧目录里有没有 `story.json`」，不要先去怀疑脚本坏了。

## 八、自证：它对自己的坏值必须拒绝

`--selftest`（`:228-286`）跑 **11 个坏值 ＋ 2 条禁止项断言 ＝ 13 个断言**（`:284`），
**每一个都断言「它该拒绝的那一条」出现了**（`:225-227`：不是「至少有 1 条报错」——
后者会让「因为别的原因报错」冒充成「这条检查起作用了」）。

**实测**：本机跑 `node D:\AIVideo\tools\script-only-check.mjs --selftest` →
**13/13 全绿、退出码 0**，末行逐字是
「✓ 自证通过：13 个坏值全部被拒绝，且每例拒绝的是**它该拒绝的那一条**；另有一例好值不被误伤」。
`D:\AIVideo\PROJECT.md:206` 也记着同一个读数（「13 个坏值全部被拒绝」）。

三条夹具的纪律值得抄，因为它们是这个文件自己栽过的跟头：

- **填充必须 ≥ `episodeCharsMin`**，否则「正常样本」自己就先红灯（`:234`、`:227`）。
- **变异必须真的改动了文本。** 一个拼错目标的 `.replace()` 会静默变成无操作，
  于是那一例拿「没被弄坏的样本」去断言「坏值被拒绝」——**两种结果都不构成证据**（`:254-261`）。
- **正常样本必须真的 0 problem**（`:240`），否则套件在测别的剧的规矩。
