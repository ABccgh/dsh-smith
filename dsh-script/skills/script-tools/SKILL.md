# 三个剧本域工具：参数、输出、以及边界

这三个工具由一个**宿主平面的 Cordis 插件**注册（源码 `D:\dsh-duanju-script\`，
包名 `dsh-duanju-script`）。它们把原本要肉眼解析的脚本输出变成**结构化读数**。

> **两条关于它们身份的实测结论，先记住：**
> ① 它们注册进的是**宿主的工具注册表**，因此**每个会话都能看见** —— 所以
> 「工具表里有 `duanju_gate`」**只能证明这一行挂上了，不能证明当前是这个 preset 的会话**
> （`index.js:22` 逐字）。同理，`bin\presets.mjs:113-121` 明确写着：**不把 `duanju_*` 名字列进
> `expectedTools`**，因为那会在每个 preset 上都成立，是一条同义反复。
> ② **它们不是工具链本身。** 权威是 `D:\AIVideo\tools\` 下的脚本 ——
> `duanju_gate` 一条检查都不重实现，它只是跑脚本并把 `findings[]` 原样透出
> （`index.js:208-212`）。所以「工具报了 PASS」与「脚本报了 PASS」是同一件事；
> 而「工具报不出来了」有它自己的含义（第三节）。

## 一、精确参数表

| 工具 | 参数 | 必填 | 返回 |
| --- | --- | --- | --- |
| `duanju_gate` | `series`（剧目录绝对路径，含 `story.json` 的那一级） | ✅ | 一份结构化契约检查报告 |
| | `range` —— **本 preset 只使用 `'script-only'`** | ✅ | |
| `duanju_recall` | `series`（剧目录绝对路径） | ✅ | 全剧状态投影（只读） |
| | `backfillFrom`（读数文件位置覆盖） | 否，缺省 `<剧目录>\评估报告-回填.json`（`index.js:677`、`:808`） | |
| `duanju_checkpoint` | `series` | ✅ | 受管区块写入报告 |
| | `dryRun`（布尔） | 否；`true` 只渲染不落盘（`index.js:463`） | |

**`range: 'script-only'` 走的是另一份脚本。** 这不是同一份闸门的另一种范围，
而是**换脚本**：`duanju_gate` 为它转调 `D:\AIVideo\tools\script-only-check.mjs --series <剧目录>`
（`index.js:367-369`）。那一份**没有 JSON 模式**，只打人类可读的三态行
（`? [UNAVAILABLE] …` / `✗ [FAIL] …` / `✓ [PASS] …`，加一行 `汇总：…`），
所以分类器为它单独走一条**文本解析**路径（`rules.mjs:43-49`、`:109-135`）。
逐字判据见 `script-rules` 技能。

> ⚠️ **为什么只剩这一个取值，以及怎么核实。**
> 旧版本的 `range` 有四个取值（`episode` / `series` / `cross-episode` / `script-only`），
> 前三个**全部以分镜表存在为前置**：`--cross-episode` 无分镜表即早退，E21–E31 一条都不跑；
> `--episode N` 缺 CSV 即早退，E1–E20 一条都不跑（`script-only-check.mjs:8-9` 把这两条早退写成了它存在的理由）。
> 实测佐证：本项目对一份**只有正文**的交付跑闸门，`--series-check` 得到
> **1 FAIL（E19「没有分镜表」，与正文无关）＋ E19b PASS**，`--cross-episode` 得到
> **只有 1 条 UNAVAILABLE（E21）**（`D:\AIVideo\PROJECT.md:208-209`）。
> 分镜表移出本 preset 之后，那三个范围没有输入可判。
> **但请现读工具表确认这一点。** 我读到的插件源码里 `range` 的枚举**仍是四个值**
> （`index.js:358`），注册表里**也仍是六个工具**（`TOOLS_META`，`index.js:204-253`）。
> 所以：**以工具表实际报出的 `range` 枚举为准**；本 preset 只使用 `script-only` 这一个，
> 另外三个取值范围**不要调用**，它们的输入在这里不存在。

**一条值得抄的设计：工具的必填参数缺失时，它不猜一个值。**
它会直说「这不是通过，是这次调用没成形」（`index.js:371`；那句原文是针对旧的
`range: 'episode'` 没给 `episode` 的情形写的，**那个范围在本 preset 里已经不用了**）。
⇒ **任何工具报「这次调用没成形」时，去补参数，不要往下走。**

**分镜表、它的 28 列、以及平台的 xlsx 导入模板**已随那三个取值范围一起移出本 preset，
服务它们的旧工具（`duanju_contract` / `duanju_board` / `duanju_template`）也不在本 preset 的范围内 ——
**不要去找、不要调用。**

## 二、四态：`PASS` / `FAIL` / `UNAVAILABLE` / `CRASHED`

报告以 `# 剧本闸门 · <态>` 开头（`rules.mjs:185`），然后是剧目录、范围、命令、退出码
（`:187-190`），再是汇总与逐条 `findings`。

| 态 | 含义 | 能不能当绿灯 |
| --- | --- | --- |
| `PASS` | 判完了，没有 FAIL 也没有 UNAVAILABLE | ✅ 仅对**它判过的那些检查**是绿灯 |
| `FAIL` | 判完了，确认不通过 | ❌ 逐条读，别只看条数 |
| `UNAVAILABLE` | **跑不了**（缺文件/缺目录），没判 | 🔴 **不是通过** |
| `CRASHED` | 脚本崩了，或**参数用错** | 🔴 **不是通过** |
| *（`USAGE`）* | `CRASHED` 的用法错变体，正文版式相同 | 🔴 同上 |

`rules.mjs:41` 的数组里有**五个字符串** `['PASS','FAIL','UNAVAILABLE','CRASHED','USAGE']`，
而源码自己的注释管它叫**四态**（`:40`：`/** 工具会把哪些整体态打印出来 —— 四态，不是三态。 */`）——
`USAGE` 是 `CRASHED` 的分支，渲染时与它合并处理（`:193`）。**别把五个字符串当成五态报出去。**

### 判据是「stdout 能不能解析」，不是退出码

闸门自己文档里的退出码是 `0/1/2/3/4`，**而 `4` 在代码里不可达** ——
崩溃与用法错误**都是 `1`**（`rules.mjs:151` 把这句话写进了 `reason`；
`script-only-check.mjs:18` 也写着同一组约定）。
所以分类器的判据是：

- **文本方言**（`script-only` 走这条）：先找 `?/✓/✗/!` 开头带 `[PASS|FAIL|UNAVAILABLE]` 的标记行
  （`rules.mjs:122`），以及 `汇总：` 行；**两样都没有**，就看 stderr 里有没有
  `用法错误` / `未知参数` / `需要一个值` —— 有就是 `USAGE`，没有就是 `CRASHED`（`:139-153`）。
- **有判据行**时，整体态从 findings **现算**：有 FAIL 就是 `FAIL`，否则有 UNAVAILABLE 就是
  `UNAVAILABLE`，否则 `PASS`（`:156-159`）。**退出码不参与结论。**

> **这条设计是跑出来的，不是读出来的**（`rules.mjs:51-53` 逐字）：最初的实现只认 JSON，
> 于是 `range=script-only` 的一次**完全正常**的运行（退出码 3 = 有 UNAVAILABLE）被报成 `CRASHED` ——
> 「**一个健康的东西被自己的分类器说成崩了**」。四态设计的价值正好在这里：
> 它没有安静地把它折成一个 `PASS`。

### ⚠️ 一条我实测过的反直觉路径：退出码 3 可能被判成 `CRASHED`

剧目录里**没有 `story.json`** 时，`script-only-check.mjs` 走的是
`console.error('读不到 story.json —— 判不了（**不是通过**）')` ＋ `process.exit(3)`
（`script-only-check.mjs:308-309`）—— **stdout 一个字节都没有**。
而分类器判「这次到底跑没跑」靠的是 stdout 里有没有判据行或 `汇总：` 行（`rules.mjs:140`）。

**实测（本机跑过）**：那份运行的 stdout **0 字节**、stderr **61 字节**、退出码 **3**；
把这份读数喂给插件自己的分类器，它返回 **`CRASHED`**，`reason` 逐字是
「没有拿到任何判据行、也没有汇总行 ⇒ 按**崩溃**记」。

⇒ **看到 `CRASHED` 时，先检查剧目录里有没有 `story.json`。**
净效果仍然是**不是通过**（`UNAVAILABLE` 与 `CRASHED` 都不是），但**标签会是 `CRASHED`**，
而它与你「脚本文没了」的直觉相反。这一处的不一致值得记住，也值得报给下一轮去修。

## 三、读 `findings` 的四条纪律（工具每次都会在末尾重印）

1. 「`?` 是**跑不了**（缺文件/缺目录），与 `✗` 一样非零退出，**绝不是通过**。」（`rules.mjs:221`）
2. 「某个 code 没出现在上面，**不等于它过了**：`E5`/`E6` 在圣经读不到时会**故意什么都不发**，
   由 `E0-输入完整性` 代言。」（`rules.mjs:222`）
   —— 源码对渲染层的要求是「**否则空白会被读成绿灯**」（`:31`）。
3. **`findings` 是 list，不是 map。** 同一个 code 可以出现多次
   （旧口径里 `E24` 最多 3 次、`E11` 有 8 个发射点、`E9`/`E9a`/`E9b` 可为同一原因同时出现）。
   **按 code 取首条会静默丢掉结论** —— 按出现顺序整体读。报告里的排序是
   FAIL → UNAVAILABLE → PASS（`rules.mjs:211-213`），那是**渲染顺序，不是重要性顺序**。
4. **`UNAVAILABLE` / `CRASHED` 不许折叠进 `PASS`。** 引用报告时把上面两句一起带上。

**`CRASHED`/`USAGE` 的报告里没有任何判据结论**，源码把它说得很直白
（`rules.mjs:193-199`）：「闸门**没有跑完**，所以这里没有任何判据结论」
＋「**这不是失败，也不是通过 —— 是没跑。** 修掉上面这条，再跑一次。」
**findings 为空也不要读成全过**：「闸门一条 finding 都没有输出。**这不等于全过**」（`:206-208`）。

## 四、每个工具的输出形状（读之前先知道该找什么）

**`duanju_gate`** —— 见第二节。文本方言的解析细节：标记行里的东西**短且没有句读**时按 `code` 看，
否则整段按 `detail` 看，而**缩进更深的下一行是 `detail` 的续行**（`rules.mjs:122-134`）——
最初的解析器把续行丢了，「等于把最有用的那半句扔了」（`:115-116`）。

**`duanju_recall`** —— 一部剧当前状态的**只读投影**，分节列出：`story.json` 的集数与时长、
`manifest.json` 的平台模式与分辨率、`bible\` 四件的条数与 id 前缀、
`script\` 下导入件的命名与**非空白字数**与分集标记用到的字（是否混用、是否超 10 万字）、
以及 `评估报告-回填.json` 的最新读数与 **delta**。
**每一节都区分「读到了」与「读不到」**，末尾重印一句：

> **读不到一律不等于通过。** 下一步该做什么由你决定，不由这份投影决定。（`index.js:454`）

⚠️ 它也会列出**分镜表**的集数与列契约。**本 preset 不产出那个目录，所以那一节会是「读不到」** ——
**那不是通过，也不是缺陷**，只是这份交付物里没有它。

读数自洽性的判据与限度见 `script-review` 第三节（源码 `rules.mjs:633-710`）。

**`duanju_checkpoint`** —— 写入报告，四行左右：目标路径与动作
（`replaced` / `appended` / `created`）、**`标记外字节：逐字节保全`**
（或一句红色告警「🔴 **变了** —— 这是缺陷，请立刻用 git 比对」，`index.js:555`）、
字节数前后对比。**标记不成对时它拒绝写入**，文件一个字节都没动；
`dryRun: true` 时它把将要落入区块的正文原样打印出来、**不写任何字节**（`index.js:517-518`）。
受管区块的纪律（只改两个标记之间的字节、标记行在哪）见 `drama-project-memory` 第六节。

## 五、什么时候用工具，什么时候必须回到 `node`

**规则一句话：工具做得到的，用工具；做不到的，明确说「工具不做这个」再跑脚本。**

| 要做的事 | 用工具 | 工具**做不到**的部分 → 回到 `node` |
| --- | --- | --- |
| 正文契约检查（集标记/四类行/字数/台词比/`story.json` 一致/禁止项） | **`duanju_gate`，`range: 'script-only'`** | **无需回退** —— 它就是转调 `script-only-check.mjs`，不含额外判据 |
| 一部剧的当前状态 | **`duanju_recall`** | **写**受管区块之外的任何东西都不在它范围内 |
| 写 `项目总览.md` 的受管区块 | **`duanju_checkpoint`** | **没有回退** —— 手写会破坏受管区块，下一个写入者会覆盖你 |
| 从 `episodes\第NN集.json` 重拼整部正文 | ❌ 不做 | `node D:\AIVideo\tools\episode-build.mjs --series <剧目录> --all --script`（加 `--check` 只校验不写盘，实测可用、退出 0） |
| 审 `story.json` 里的 `hook3s` 与 `cliffhanger` 有没有落点 | ❌ 不做 | `node D:\AIVideo\tools\hook-audit.mjs --series <剧目录>`（退出码 0 / 2 / 1） |
| 圣经与素材台账 | ❌ 不做 | `node D:\AIVideo\tools\asset-manifest.mjs --series <剧目录> --check` |

**工具没有覆盖的，就是必须自己跑 `node` 的那部分 —— 不要因为工具表里没有就跳过它。**
`hook-audit.mjs` 尤其容易被漏：它判的 `hook3s` **不在**机器契约里（`script-gate.mjs` 的 E28
只检 `cliffhanger`），缺口与实测例子写在 `script-rules` 第五节。

## 六、工具本身的可信边界（写下来，免得当成绝对权威）

- **`duanju_gate` 的结论全部来自脚本**。工具自己的判断只有两个：分类成哪一态、以及渲染。
  所以它的可信度**等于它所转调的那份脚本的可信度**，不多也不少；脚本漏判的，工具同样漏判。
- **工具报不出来，可能是能力问题，不是通过。** 脚本不存在时它返回 `CRASHED` 并写明
  「找不到闸门脚本：<路径>」（`index.js:328-331`）。**这句是设计，不是兜底话术。**
- **`duanju_recall` 的读数自洽性只校验自洽**：它抓转述错字与「等级与总分映射不符」，
  **抓不出整份报告读错**。这句话每次都印在它的输出里，**引用读数时也要带上**。
- **`duanju_checkpoint` 只管它声明的那个区间**：标记之外的字节它是保全的，
  但它**不判断该不该写** —— 该不该更新投影，是你的决定。
