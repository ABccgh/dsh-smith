# 项目记忆：五层，各自只装一种东西

**分层的理由**：`PROJECT.md` 与 `DECISIONS.md` 加起来已超过 **250 KB**，**永远不可能整体注入上下文**。
所以每一层必须能被单独读完，而「哪一种事实进哪一层」要由**用途**决定，不是由时间决定。

| 层 | 装什么 | 谁在写 | 规则 |
| --- | --- | --- | --- |
| `PROJECT.md` | 架构与契约**已核实**的事实、当前状态、**刻意未完成**的东西 | 每个里程碑之后 | 可以被改写：删掉现在已假的，别让它在原地被矛盾 |
| `DECISIONS.md` | 一个已决的问题：决定、理由、**什么会推翻它** | 决定了什么的时候 | **只追加。永不改写、永不重排。** 改了主意就写一条**新**条目，并点名它取代了哪条 |
| `INVENTORY.md` | 文件与资产的台账（哪些是权威、哪些可再生、哪些不可再生） | 产物面变化时 | 数字只写能从盘上重数出来的；会被改写的那类写**路径**而不是计数 |
| `products\<剧名>\评估报告-回填.json` | 平台评估的**读数**层 | 每次读数回来 | `readings[]` **只追加**；顶层便捷副本同步成最新；维护 `_待我做的` |
| `products\<剧名>\项目总览.md` | 该剧当前状态的**机器投影**，人读部分在受管区块之外 | **只有 `duanju_checkpoint`** | 只重写两个标记之间的字节；标记之外的字节**逐字节保全**（见第六节） |

## 一、读回来：顺序是固定的，而且是机械的

会话开始读回项目状态时，**按这个顺序**：

1. **先读 `PROJECT.md` 的最新一节** —— 当前状态在这里，不在开头。
2. 再读 `评估报告-回填.json` 的 **`_待我做的`** —— 当前真实的阻塞项在这里。
3. 需要时**只查 `DECISIONS.md` 里相关的那几条**。**不要整份读它** —— 它与 `PROJECT.md` 合计已超 250 KB，整体读既读不完也会把上下文淹掉。

**写之前先读，现在是机械动作，不是自我提醒：**

- **动手记录任何东西之前，先跑一次 `duanju_recall`**（`series` = 剧目录绝对路径）。它一次调用就把整部剧的状态摆出来：
  `story.json`（集数/时长/分集功能表条数/设计是否冻结）、`manifest.json`（平台模式/模板/分辨率/比例）、
  `bible\` 四件的条数与 id 前缀、`storyboards\` 的集数与列契约、`script\` 下两份导入件的命名与字数、
  以及 `评估报告-回填.json` 的最新读数与 delta。
  它**只读、只报**，并把「读到了什么」与「读不到什么」分开列 —— **读不到一律不等于通过**。
- **往一个文件里写之前，先读那个文件自己的头。** 确认它的格式与它声明的不变量，再决定写哪几段。
  这一条对**要写进去的那个文件**成立，`duanju_recall` 的投影**不能替代它**：投影是「这部剧现在是什么样」，文件的头是「这个文件要求怎么写」。两者都要读。
- 工具的精确参数、输出形状与四态语义见 **`script-tools` 技能** —— 本技能只规定**什么时候**必须调它，不复制它的参数表。
- 目录布局、产物命名与产物面的归属见 **`drama-workspace` 技能**，工作区契约由它拥有。

## 二、两条贯穿全部五层的规则

### 规则一：**没能核实的一律写成开放问题，不写成结论**

一条没核实的断言写下来，下一次会话会把它当成已核实的事实读回去 —— 它会在一个矛盾出现之前一直安静地正确。
所以：**写下的每条结论都要能指出它是从哪个文件、哪条命令、哪次读数来的**；指不出来，就写成**开放问题**。
**推断必须标成「推断」**，并写出什么能把它证成或证伪 —— 标成推断的句子仍然有用，没标的句子有害。

### 规则二：**平台的规则不进记忆层**

平台的评分口径、评级映射、闸门条件、表头列名 —— 这些是**平台侧的事实**，它们会变。
冻结一份进记忆层，下一次平台改动就把它变成谎话，**而且没有任何检查会因此变红**。

**它们以「引用」的形式旅行**：带上出处 —— **哪个前端产物、哪一行、什么时候读的**。
记忆层里留下的是**项目**：写了什么、闸门报了什么、平台返回了什么、决定了什么、排除了什么、还开着什么。

## 四、`DECISIONS.md` 的条目形状

每条至少四段，缺一段的那条不算决策：

```
## D-NN 一句话题目

**触发。** 什么情况让这个问题必须被决定。

**决定。** 决定了什么。

**为什么。** 理由 —— 这一段是这条记录存在的意义。没有它，未来的人无从判断它是否适用于自己。

**什么会推翻它。** 具体的可观察条件。
```

**「什么会推翻它」不是客套。** 它是这条记录的解约条款：没有它，一条曾经正确的决定会永远正确下去。

## 五、读数层的证据等级（本项目的特有纪律）

平台读数在**本项目里全是用户在会话中的转述** —— 本机没有该平台的登录态，**读不到报告文件，也读不到截图**。所以：

- 写读数时，**把「它是转述」写进那一层**（回填文件里那条是 `_真实性说明`）。
- `duanju_recall` 对读数的检查**只证明那个文件自洽**（顶层副本与 `readings[]` 末条一致、`grade` 与总分映射一致、五维 id 顺序与均分 ×10 相符），
  它**抓的是转述错字，抓不出整份报告读错**。这句话每次都印在它的输出里，**引用读数时也要跟着出现**。
- 能拿到导出件或截图时，补进 `_原报告来源`。
- **不要**把一条转述升格成实测。它的可复核程度低于一次实测读数，但高于推理 —— **如实写这个位置**。
- 不同评估方的量纲**不可相减**（来源同上：有戏AI 0–100 五维、剧云 0–100 六维、PageOne 0–10）—— **别把两次读数放进同一个 `readings[]`。**

## 六、受管区块：只写两个标记之间的字节

`products\<剧名>\项目总览.md` **只由 `duanju_checkpoint` 写**。它的机器部分是这两行之间的一切：

```
<!-- BEGIN duanju-overview (managed; do not edit by hand) -->
<!-- END duanju-overview (managed; do not edit by hand) -->
```

- 标记串的定义在 `D:\dsh-duanju-script\lib\rules.mjs:715` 与 `:717`；只管区间的那段在 `rules.mjs:731-753`。
- **只有 `duanju_checkpoint` 写标记之间。** 不是 agent，不是 chronicler，不是手改。
- **标记之外的字节逐字节保全。** 工具写完会**回读文件**并印出 `标记外字节：逐字节保全`，或者一句红色告警 —— 那一行是读数，读它。
- **标记不成对**（只有头、只有尾、或顺序颠倒）⇒ `rules.mjs:745-750` **抛错，工具拒绝写入，文件一个字节都没动**。它**绝不猜区间**：猜错区间就是删掉用户的文件。手工把标记补齐，或删掉那半行再重跑。
- **目标文件不存在时**，工具新建它：一个标题行加受管区块。
- **`dryRun: true` 只渲染、不写盘**（`D:\dsh-duanju-script\lib\index.js:826-833`）。**文件已经存在时先跑一次 `dryRun`。**
- **受管区块不属于「平台规则」那一类**：它只是**读数**（集数、分集功能表条数、分镜表张数、最新读数与自洽性），**没有冻结任何平台口径**。所以它可以进记忆层，而规则二不受影响。
- **「哪些文件带受管区块」要重读，不要记。** 实测：`asset-manifest.mjs:117` 写 `products\<剧名>\bible\README.md` 那一个（标记在 `asset-manifest.mjs:35-36`），
  在本工作区里**除它以外没有别处带受管区块**；`项目总览.md` 是第二个，且**只对跑过 `duanju_checkpoint` 的剧存在**。这个清单会变。
