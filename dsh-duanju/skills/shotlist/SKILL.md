# 分镜表：唯一权威格式

分镜表是本工作台**最贵的文件**。理由不是它难写，而是它错了以后，代价在生成阶段**乘性放大**：
`script-gate.mjs` 记录本工作台实测一个镜头要重拍 3–6 次，而 720p/10s 一次就是 140 算力。
所以这份技能的第一原则是：**把错误挡在花钱之前**。

> **本 preset 的重心是正文**，见 `dramaturgy`、`hook-ladder`、`episode-engineering`、`script-delivery`。
> 分镜表是正文的**产物**：平台评估只读正文、分镜表一个字都不读。本技能管的是**形状那一环** ——
> 正文定下来之后，28 列分镜表必须形状正确，否则生成与导出会在你没注意的地方错位。

## 一、平台吃进去的到底是什么（实测，不是推断）

有戏AI 有**两条完全不同的导入路径**，格式要求也不同：

| 路径 | 载体 | 允许格式 | 分集/解析规则 |
| --- | --- | --- | --- |
| **① 剧本导入** | 纯文本 textarea，**无文件上传** | 粘贴文本 | 用 `第n章` 或 `第n集` 分割 |
| **② 导入分镜表** | **文件上传** | **只认 Excel `.xlsx` / `.xls`** | 按模板列解析 |

来源：平台前端构建产物 + 官方教程正文（两处印证）。原文：

> 请导入剧本，将为你自动分集（文本请用"第n章/集"分割）
> 剧本支持10万字以内，长剧本需要分集，**每一集必需控制在2000字以内**
> **注意：不能混合使用**，比如在同一个剧本中，同时使用：第1章， 第2集 ，这样是不能分集的

⚠️ **这两条是本技能里唯一「平台上真的会拦你」的规则**，其余都是我们自己的纪律。代码出处：
`script-gate.mjs:240` 的 `PLATFORM_EPISODE_CHAR_LIMIT = 2000`、`:241` 的 `PLATFORM_SCRIPT_CHAR_LIMIT = 100000`
（注释都写着「官方原文」），分集标记混用的断言在 `:2255`。

篇幅是**内容判据**，不只是格式判据 —— 本项目实测：全 12 集 **2 526 字**（每集约 210 字）平台判 **D 55.7**；
改写后全 12 集 **20 554 字**（每集 1 630–1 895 字）判 **A 82.6**，五维全部上升。所以目标是**每集 1 600–1 900 字**；
两条硬上限 **2 000 字/集**与**全集 ≤10 万字**是平台原文，**超了是拒收，不是扣分**。

## 二、列契约：权威是代码里的**数组字面量**

本地分镜表路径：`products/<剧名>/storyboards/第NN集-分镜.csv`
**顺序自由，但一个都不能少；多一列就报错**（拼错的列名静默通过是最坏的一种通过）。

> **唯一权威是代码，不是这份文档。** 列清单是 `D:\AIVideo\tools\script-gate.mjs` 里的 `REQUIRED_COLUMNS`
> —— **实测位于 `:87`–`:118`，28 个字符串条目**。**要用它就去读它**，不要引用任何文档里的列数 —— 包括这一份。

**首选路径是 `duanju_contract`，不是手工去读那个数组。** 它从数组字面量**机械抽取**，再做三段对照：
① 闸门源码里**与数组不符**的「N 列」说法（逐条列出行号）；② 三份官方模板的实测列矩阵（带 sha256）；
③ 给了 `series` 时再对照这部剧本地的分镜表。它抽不到数组时**抛错，绝不返回空数组** ——
空数组会被下游读成「没有列要求」。`series` 可省略，**省略时第 ③ 节没跑，报告会明说「这一节没跑，不是通过」**。

### 为什么不能引用文档里的数字：这个文件自己就有三处不一致

| 位置 | 它说的列数 | 与数组的关系 |
| --- | --- | --- |
| `script-gate.mjs:29` | 本闸门吃 **20 列** | ✗ 陈旧 |
| `script-gate.mjs:34-35` | 自我订正，又写 20 | ✗ 陈旧（**「订正」也可能停在旧值上**） |
| `script-gate.mjs:443` | HELP 打印「**25** 列表头」 | ✗ 陈旧 |
| `script-gate.mjs:87-118` | **28** 个条目 | ✅ **权威** |

`:72` 自己写着：「**列数以 `REQUIRED_COLUMNS`（下方）为唯一权威** —— 本注释里的数字落后过它，所以不要再写死一个数。」
`board-to-xlsx.mjs:3` 也写 25 列，同样陈旧。成因是 **文档里的数字落后代码不会让任何测试变红**，
所以它只能靠纪律挡住 —— 纪律就是「去读数组」或「问 `duanju_contract`」。

### 28 列的三段来历

| 段 | 列 | 来历 |
| --- | --- | --- |
| 引用自洽组 | 第 1–20 列 | 原有的 20 列（官方 15 列去 2 个提示词列 + 7 个本地质检列） |
| 叙事结构组 | 第 21–25 列 | **D-14**（`DECISIONS.md:352`）：叙事结构落在分镜表上，而不是另开一张表 |
| P1/P2 判据组 | 第 26–28 列 | **D-20**（`DECISIONS.md:569`）：把 P1/P2 的验收标准变成可判的 |

引用自洽组管「这堆字符串互不矛盾」；叙事结构组管「这一集是不是一个完整的故事单元」；
P1/P2 判据组把平台 P1 验收里那条**跨集链式条件**变成可判的（见第五节）。

## 三、三份官方模板，以及三个必须单独记住的陷阱

三份模板实测在 `D:\AIVideo\research-youxi\templates\`；平台自己的下载文件名是 `shot_import.xlsx`
（**实测与 `分镜模板_旁白.xlsx` 同大小，都是 11 909 B**）。

| 模板 | 列数 | 表头（**第 3 行**原文） |
| --- | --- | --- |
| `分镜模板_剧情_生图转视频.xlsx` | **15** | 镜头 镜头剧本 分镜号 景别 构图 运镜 光影 场景 站位 分镜描述 音效 对白 时长 镜头图片提示词 镜头视频提示词 |
| `分镜模板_剧情_参考生视频.xlsx` | **13** | 镜头 镜头剧本 分镜号 景别 构图 运镜 光影 场景 分镜描述 音效 对白 时长 镜头视频提示词 |
| `分镜模板_旁白.xlsx` | **6** | 分镜号 分镜剧本 场景 对白 分镜图提示词 分镜视频提示词 |

⚠️ **这张表被改错过一次，而且改的方向是反的，所以留痕在这里。** 它先写成「`参考生视频` 删掉的是『站位』与『镜头图片提示词』」
（**这句是对的**），随后被「更正」成「也删掉了『分镜描述』」——**那次「更正」才是错的**。
权威不是这张表，是**解出来的 xlsx 本身**：实测 13 列里有 `分镜描述`，没有 `站位`、也没有 `镜头图片提示词`。
`board-to-xlsx.mjs:59-60` 的表头数组写对了。**列名表错一格，导出的表就会整体错开一格 —— 而错位不会报错。**

### 陷阱 1：官方模板的表头在**第 3 行**，不是第 1 行

模板的**前两行是注释行**，导入前**必须删除**。第 1 行原文就是这句，而第 2 行的最后一个单元格写着
**「导入分镜表前请删除此行」**（三份模板实测都有）：

> 注意事项：此模板的第1，2行是注释行，导入分镜模板前，请将前两行删除

| 读的是谁 | 表头在第几行 | 为什么 |
| --- | --- | --- |
| 官方模板 | **第 3 行** | 前两行是注释行 |
| 一份**导出件** | **第 1 行** | 与模板不同 —— 读之前先知道自己读的是哪一个 |

⚠️ **忘记删前两行会在平台上失败，而本地没有任何东西会拦你** —— 它对本地所有断言都是隐形的。
`duanju_template` 就是为这件事存在的：给了 `compareWith` 时它**分别说明**两边表头在第几行，
并在导出件里还留着注释行时直接报 `✗`，同时告诉你「平台会在导入时失败，而本地任何断言都不会红」。

### 陷阱 2：多出来的那个**空字符串单元格**（数格子会被骗）

**每一份官方模板都有一个尾随单元格 —— 它存在，但存的是空字符串**（实测，三份都有，所以不是某一份的怪癖）。
于是数单元格得到 **16 / 14 / 7**，而真实列数是 **15 / 13 / 6**（见上面那张表）。
**不要被它骗的办法：数表头的「名字」，不要数单元格。**
`duanju_template` 把空字符串单元格渲染成 `∅` **并报告出来，而不是替你抹平** —— 那正是它存在的理由。

### 陷阱 3：旁白模板没有 `时长`，而它的提示词列名差一个字符

1. **它没有 `时长` 列**（本地 28 列的 `:100` 才是 `时长`）。导出时若按「剧情」模板的列序去填，
   **差一列就会整体错开**；旁白模式下的时长只能由平台决定。
2. **它的列名是 `分镜图提示词`，不是 `镜头图片提示词`** —— **差一个字符**。
   按「剧情」列名去对照、或用字符串相等去匹配，都会匹配失败，而失败是静默的。

三份模板的完整字节读（表头行、逐单元格预览、sha256）都由 **`duanju_template`** 给出：`template` 传模板文件名，
`compareWith` 传一份导出件的绝对路径（`.xlsx` 或 `.csv` 都认）。模板目录读不到时它说「**这不是通过，是判不了**」。

**平台自己的语法示例（模板正文原文）**：`参考主体格式为：@[主体]，例如，@[凌霄]，@[八卦炉]，@[兜率宫内-八卦炉区]`。
模板给出两种使用方式 ——「使用方式一：导入分镜信息后系统生成提示词」与「使用方式二：直接导入图片和视频提示词」。
**我们采用「使用方式一」**：填分镜信息，让系统生成提示词。理由是那些提示词列里有平台自己的
Shot 语法与主体替换逻辑，我们自己拼只会更差；而**分镜信息的正确性恰恰是我们能静态校验的部分**。

## 四、本地 28 列（闸门吃的那张表）

分三组。**第 26–28 列不在这张表里展开**，原因见下。

| # | 列名 | 必填 | 取值与约束 |
| --- | --- | --- | --- |
| 1 | `镜头` | 是 | 纯数字序号 |
| 2 | `镜头剧本` | 否 | 该镜头对应的一句剧本，**只为人读** |
| 3 | `分镜号` | 是 | 集内唯一，形如 `1-1`。重复即 E2 FAIL |
| 4 | `景别` | 是 | **必须在词表内**（见第八节） |
| 5 | `构图` | 是 | 同上 |
| 6 | `运镜` | 是 | 同上 |
| 7 | `光影` | 是 | 写光源方向与对比度，不写「氛围很好」 |
| 8 | `场景` | 是 | **必须等于 `bible/scenes.json` 里的 `name`**（不是 id） |
| 9 | `站位` | 是 | 谁在画面哪个位置、离某物多远 |
| 10 | `分镜描述` | 是 | 画面事实描述。**`@[X]` 引用写在这里** |
| 11 | `音效` | 否 | 无则写 `-` |
| 12 | `对白` | 否 | 格式 `角色名：台词` 或 `旁白：…`。无则留空（**不要写「无」**） |
| 13 | `时长` | 是 | 秒。**必须落在已实测单价的档位内**（见第九节） |
| 14 | `画面类型` | 是 | 见第六节 |
| 15 | `可作首帧` | 是 | 只能 `是` / `否` |
| 16 | `参考图` | 是 | `;` 分隔的**文件名**，须真实存在于 `assets/`，**不得以下划线开头** |
| 17 | `出场角色` | 条件 | `;` 分隔的**角色 id**（`C-01`），不是名字。`空镜` 时留空 |
| 18 | `动作主体` | 条件 | **单个角色 id**，且必须在本镜 `出场角色` 内 |
| 19 | `所持道具` | 否 | `;` 分隔的 `道具id>持有者id:动作`，如 `P-02>C-01:挥拍`。空镜写 `P-03>:-` |
| 20 | `音色` | 条件 | 有对白时必填，取值来自 `bible/voices.json` 的 `id`（`V-01`） |
| 21 | `镜头功能` | 是 | `铺垫` / `冲突` / `转折` —— **三幕位置的唯一来源**，E14 按它算时长占比 |
| 22 | `集尾卡点` | 是 | `是` / `否`。**每集恰好一个 `是`**，且它必须落在最后 20% 时长内（E15） |
| 23 | `对白类型` | 条件 | `对白` / `旁白` / 空。有台词时填 |
| 24 | `对白功能` | 条件 | `施压` / `掩饰` / `反击`。**有对白必须填**；无对白必须留空（E17） |
| 25 | `节拍` | 是 | `目标` / `阻碍` / `升级` / `转折` / `新局面` —— 五段每集至少各一次（E16） |

### 第 26–28 列（D-20 立项，E21–E23 判）

`变化维度` / `变化状态` / `主动性`。这三列**不在这张表里展开**，因为它们的取值与必填性由代码判定 ——
去读 `script-gate.mjs` 里的 `E21-变化声明` / `E22-变化链继承` / `E23-主动性证据`，或直接跑 `duanju_gate`。
它们要解决的是另一类问题：平台 P1 验收要求「第2至10集每集除新增信息外，至少改变目标、关系、资源或风险中的一项，
**并由下一集继承**」—— 那是**跨集**条件，单集闸门在设计上就看不到它。

## 五、叙事结构组这 5 列解决什么

**没有它们，闸门只能判「这堆字符串互不矛盾」，判不了「这一集是不是一个完整的故事单元」。**
而这正是本工作台最贵的一种错：片子看起来没问题，播出去没人看完 —— **那不是语法错，是结构错**。

| 列 | 它让什么东西可判定 |
| --- | --- |
| `镜头功能` | 三幕比例（30/50/20%）与「每一幕非空」 |
| `集尾卡点` | 钩子是否真的落在尾部（而不是随便哪一镜） |
| `节拍` | 因果链五段是否齐；同一段有没有被灌水拉长 |
| `对白功能` | 对话有没有权力/信息的攻防变化（而不是「毫无立场的解释性闲聊」） |
| `对白类型` | 对白密度的口径（对白 vs 旁白）；也是走向「旁白解说模式」时的预留 |

⚠️ **这 5 列整列为空时，E13–E18 一律报 UNAVAILABLE**，不是 PASS ——
「读不到」与「没问题」必须区分（见 `script-tools` 与 `script-delivery`）。

`出场角色` / `动作主体` / `所持道具` 是**特意分开**的三列，为的是让这类错**静态可拒绝**：
历史实例（本项目早期，不作为现行项目）某个镜头的动作是「挥拍击球」，引用的却是**球**的资产 ——
两个画布节点都叫「生成物品三视图」，**靠标题永远区分不出来**，只有看图才发现。
拆开之后闸门能断言「持有者必须在本镜出场角色内」且「动作必须在该道具的 `allowedActions` 内」；
合并成一列「道具：球拍（挥拍）」就退化成散文，机器判不了。

## 六、`画面类型` 的取值与它挡住的那类错

| 取值 | 含义 | 要求 |
| --- | --- | --- |
| `角色三视图` | 圣经里的角色素材 | 至少一个出场角色 |
| `物品三视图` | 圣经里的道具素材 | 同上 |
| `场景俯视图` / `场景图` | 圣经里的场景素材 | 同上 |
| `首帧图` | 某个镜头的生成输入 | 至少一张可解析的参考图 |
| `空镜` | **没有角色**的画面（只有物件/环境） | 出场角色必须为空、对白必须为空 |
| `联络表` / `拼图` / `QC报告` | **产物**，不是素材 | **一律拒绝作为生成输入** |

最后一类存在的原因是一次实测事故：

> QC 生成的联络表 `_contact-sheet.png` 是 **1480×744 的横向拼图**，被「取最新文件」逻辑
> 当成了首帧，导致输出 **960×960（1:1）** 而不是 9:16。
> **缺陷在选图逻辑，不在生成服务** —— 但它伪装成「服务不遵守比例」。

所以本工作台有一条硬纪律：**永不「取最新文件」**。素材只认「参考图」列里显式声明的文件名。

## 七、`@[主体]` 引用（平台自己的语法）与它的边界

`@[X]` 里的 X 是**主体名**，不是 id。合法的主体名来自三张圣经表的 `name` 字段：

- `bible/characters.json` → 角色名
- `bible/props.json` → 道具名
- `bible/scenes.json` → 场景名

闸门 **`E7-主体引用`** 会把每一个 `@[X]` 拿去主语表里查，查不到就 FAIL（发射点在 `script-gate.mjs:2131-2135`）。
这条的价值在于：**写错的主体名平台不会报错，只会让画面漂** —— 那是花钱之后才发现的事。

⚠️ **已知边界（不要越界声称）**：**我们只验证 `分镜描述` 里的 `@[X]`。**
官方模板自身在**提示词列**里的示例（`背景是@[兜率宫内-八卦炉区]`）用的是同一套语法，
但平台在「使用方式一」下**是否也对我们填的分镜信息做主体替换、替换范围到哪一列，我们没测过**。
这是**平台行为，不是文件属性**，必须实测才能断言 —— 在上述实测发生之前，任何把它说成「平台会替换」的句子都是没有依据的。

## 八、镜头语言词表（落在表外即 FAIL）

固定词表的理由：同一件事有多种写法时（「推镜」/「缓慢推进」/「慢推」），跨镜头的风格会**静默漂移**，

- **景别**：特写 近景 中景 中近景 全景 远景 大远景

要加新值就改 `script-gate.mjs` 里的 `SHOT_SIZES` / `COMPOSITIONS` / `CAMERA_MOVES`，

## 十一、写完分镜表之后必须做的事

**首选 `duanju_gate`，不要手敲 node：** `duanju_gate(series: "<剧目录绝对路径>", range: "episode", episode: <N>)`。
四个 `range`：`episode` / `series` / `cross-episode` / `script-only`。它在内部跑 `script-gate.mjs --format json`
并把 `findings[]` 原样透出 —— **它一条检查都不重实现**，所以「工具报 PASS」与「闸门报 PASS」是同一件事。
精确参数见 `script-tools`。回退路径（工具做不到的部分）是原始脚本：

```powershell
node D:\AIVideo\tools\script-gate.mjs --series <剧目录> --episode <N>
```

**看四态，不是看退出码。** `duanju_gate` 报告以 `# 剧本闸门 · <态>` 开头：

| 态 | 含义 | 能不能当绿灯 |
| --- | --- | --- |
| `PASS` | 判完了，没有 FAIL 也没有 UNAVAILABLE | ✅ 仅对**它判过的那些检查**是绿灯 |
| `FAIL` | 判完了，确认不通过 | ❌ 逐条读，别只看条数 |
| `UNAVAILABLE` | **跑不了**（缺文件/缺目录），没判 | 🔴 **不是通过** |
| `CRASHED` | 脚本崩了，或**参数用错**（另有 `USAGE` 变体，正文同版式） | 🔴 **不是通过** |

⚠️ **闸门文档里的退出码 `4`（运行期异常）不可达**：全文件没有 `process.exit(4)`、没有 `return 4`（实测搜索，零命中），
唯一的 `try/catch` 只包 `parseArgs`。于是**崩溃与用法错误都是退出码 1，退出码分不开这两件事** ——
看到 `1` 时先分清是参数用错还是脚本崩了，判据是 stdout 能否解析成 JSON。

⚠️ **读 `findings` 的两条纪律**（工具每次都在末尾重印）：① 「上面标 `?` 的是**跑不了**，不是**通过**。」
② 「某个 code 没出现上面，**不等于它过了**：`E5`/`E6` 在圣经读不到时会**故意什么都不发**，由 `E0-输入完整性` 代言。」
（依据：`script-gate.mjs:2066`、`:2101` 注释与 `:1836`。）`findings` 是 **list，不是 map**：`E24` 最多出现 3 次、
`E11` 有 8 个发射点、`E9`/`E9a`/`E9b` 可为同一原因同时出现 —— **按 code 取首条会静默丢掉结论**，要按顺序整体读。

**顺序纪律**：闸门 PASS 是**手艺**判据，不是内容判决；**在用户从平台带回读数之前，不许写分镜表。**
