# 分镜表：本 preset 的主产物与唯一权威格式

**分镜表在这个 preset 里是主产物，不是正文的附带物。** 上游的剧本已经由另一个 preset
（剧本工坊 · DSH Script）定稿交付 —— 本 preset 的起点就是那份正文，终点是**能生成、能过平台、能投稿的分镜表与成片**。
所以本技能管的不是「正文写得好不好」，而是**从定稿正文到 28 列分镜表的这一步，形状必须对**。

## 〇、这一个 preset 的边界（先读，免得越界）

| 属于本 preset | 属于剧本工坊，不属于本 preset |
| --- | --- |
| 28 列分镜表、逐列约束、`@[主体]` 引用 | 选题、一句话钩子、分集功能表 |
| 从分镜表到平台可导入 xlsx（见 `board-export`） | 逐集正文、台词密度、集尾钩子 |
| 生成、成片、投稿、成本闸门（见 `production-line`） | 平台的剧本评估与改稿循环 |

**分镜表是这一环的产物，但正文的权威不在本 preset 手里。** 两者必须同源：改了分镜表里的
`场景` 名或 `出场角色`，正文里对应的写法**不会被任何工具自动同步** —— 那是上游的事，改之前先问一句。

⚠️ **写作前置条件（硬纪律）**：平台的剧本评估读的是**正文**，**分镜表它一个字都不读**。
所以「上游正文是否已经拿到读者/平台的读数」这个条件不成立时，**不要写分镜表**。

## 二、列契约：权威是代码里的**数组字面量**

本地分镜表路径：`products/<剧名>/storyboards/第NN集-分镜.csv`
**顺序自由，但一个都不能少；多一列就报错**（拼错的列名静默通过是最坏的一种通过）。

### ⚠️ 本 preset 已经没有任何工具替你去读那个数组了

**曾经有一个工具 `duanju_contract` 从数组字面量里机械抽取列清单。它已随剧本那一环一起被删除。**
本 preset 现在只剩三个 `duanju_*` 工具：`duanju_gate`（只跑 `range: "script-only"`）、`duanju_recall`、`duanju_checkpoint`。
**它们里面没有一个会告诉你列契约是什么。**

**结论，请按字面理解：列契约现在没有机器判据。** 「28 列」这件事只有两个来源 ——
① 你**自己读那个数组**；② 你相信某份文档。本文件明确属于第 ② 类，所以**不要引用本文件的列数**。

读它只要一条命令（`sed` 风格的行号切片，行号是实测的）：

```powershell
# 打印 REQUIRED_COLUMNS 的数组字面量本身（实测位于 :87–:118）
Get-Content 'D:\AIVideo\tools\script-gate.mjs' | Select-Object -Skip 86 -First 32
```

或者不看行号、按名字取（数组之后**紧跟**的 `]` 才收尾）：

```powershell
Select-String -Path 'D:\AIVideo\tools\script-gate.mjs' -Pattern 'const REQUIRED_COLUMNS' -Context 0,32
```

**数条目、不要数字数**：数出 **28** 个带引号的字符串。**行号会漂**（这份技能里所有行号都是某次实测的快照），
`const REQUIRED_COLUMNS` 这个名字不会。**名字是稳定的锚，行号不是。**

### 为什么不能引用文档里的数字：那个文件自己就有三处不一致

| 位置 | 它说的列数 | 与数组的关系 |
| --- | --- | --- |
| `script-gate.mjs:29` | 本闸门吃 **20 列** | ✗ 陈旧 |

所以它只能靠纪律挡住 —— 纪律就是「去读数组」。

同族的教训还有一条：`:32` 说「逐列映射见 dsh-aivideo 的 shotlist 技能，那里是唯一的权威表」，

### 第 26–28 列解决什么

它们来自 **D-20**，把平台 P1 验收里那条**跨集**条件变成可判的：平台要求「第2至10集每集除新增信息外，
至少改变目标、关系、资源或风险中的一项，**并由下一集继承**」。那是单集闸门在设计上就看不到的条件，
所以判据由 `E21-变化声明` / `E22-变化链继承` / `E23-主动性证据` 承担。

⚠️ **这三列有一个语义陷阱，写在代码里而不是文档里**：`主动性` 的语义是关于**女主**的，
不是关于本集所有人（`:149` 的注释点名了 `C-01`）。换一部剧要换的是**这个列的含义**，
不是它的取值域 —— 取值域是词表，含义是剧的设定。

## 四、叙事结构组这 5 列解决什么

**没有它们，闸门只能判「这堆字符串互不矛盾」，判不了「这一集是不是一个完整的故事单元」。**
而这正是本工作台最贵的一种错：片子看起来没问题，播出去没人看完 —— **那不是语法错，是结构错**。

| 列 | 它让什么东西可判定 |
| --- | --- |
| `镜头功能` | 三幕比例与「每一幕非空」 |
| `集尾卡点` | 钩子是否真的落在尾部（而不是随便哪一镜） |
| `节拍` | 因果链五段是否齐；同一段有没有被灌水拉长 |
| `对白功能` | 对话有没有权力/信息的攻防变化（而不是「毫无立场的解释性闲聊」） |
| `对白类型` | 对白密度的口径（对白 vs 旁白）；也是走向「旁白解说模式」时的预留 |

⚠️ **这 5 列整列为空时，E13–E18 一律报 UNAVAILABLE**，不是 PASS ——
**「读不到」与「没问题」必须区分**（`:2429` 的 `missingNewColumns` 就是这条的实现）。

`出场角色` / `动作主体` / `所持道具` 是**特意分开**的三列，为的是让这类错**静态可拒绝**：
历史实例（本项目早期，不作为现行项目）某个镜头的动作是「挥拍击球」，引用的却是**球**的资产 ——
两个画布节点都叫「生成物品三视图」，**靠标题永远区分不出来**，只有看图才发现。
拆开之后闸门能断言「持有者必须在本镜出场角色内」且「动作必须在该道具的 `allowedActions` 内」；
合并成一列「道具：球拍（挥拍）」就退化成散文，机器判不了。

## 五、`画面类型` 的合法取值与它挡住的那类错

判据是三个集合（`:137`–`:233`）：`VALID_SCENE_KINDS`（合法域）、`CAST_REQUIRED_KINDS`（需要出场角色）、
`PRODUCT_KINDS`（纯产物）。

| 取值 | 含义 | 要求 |
| --- | --- | --- |
| `角色三视图` | 圣经里的角色素材 | 至少一个出场角色 |
| `物品三视图` | 圣经里的道具素材 | 同上 |
| `场景俯视图` / `场景图` | 圣经里的场景素材 | 同上 |
| `首帧图` | 某个镜头的生成输入 | 至少一张可解析的参考图，且需要角色（`:223`） |
| `空镜` | **没有角色**的画面（只有物件/环境） | 出场角色必须为空、对白必须为空 |
| `联络表` / `拼图` / `QC报告` | **产物**，不是素材 | **一律拒绝作为生成输入**（`:138` `NON_FIRSTFRAME_KINDS`） |

⚠️ 落在这三个集合**之外**的取值（例如拼错一个字）**整列静默失效**：`E8a` 既不会拒绝也不会要求角色，
两个分支都不进。`:1979` 的注释记着这件事，`:1981` 的断言就是为它加的。

最后一类（产物）存在的原因是一次实测事故：

> QC 生成的联络表 `_contact-sheet.png` 是 **1480×744 的横向拼图**，被「取最新文件」逻辑
> 当成了首帧，导致输出 **960×960（1:1）** 而不是 9:16。
> **缺陷在选图逻辑，不在生成服务** —— 但它伪装成「服务不遵守比例」。

所以本工作台有一条硬纪律：**永不「取最新文件」**。素材只认「参考图」列里显式声明的文件名。

## 六、`@[主体]` 引用（平台自己的语法）与它的边界

`@[X]` 里的 X 是**主体名**，不是 id。合法的主体名来自三张圣经表的 `name` 字段：

- `bible/characters.json` → 角色名
- `bible/props.json` → 道具名
- `bible/scenes.json` → 场景名

闸门 **`E7-主体引用`** 会把每一个 `@[X]` 拿去主语表里查，查不到就 FAIL（发射点在 `script-gate.mjs:2131-2135`）。
这条的价值在于：**写错的主体名平台不会报错，只会让画面漂** —— 那是花钱之后才发现的事。

⚠️ **已知边界（不要越界声称）**：**我们只验证 `分镜描述` 里的 `@[X]`。**
官方模板自身在**提示词列**里的示例（`背景是@[兜率宫内-八卦炉区]`）用的是同一套语法，
但平台在「使用方式一」下**是否也对我们填的分镜信息做主体替换、替换范围到哪一列，我们没测过**。
这是**平台行为，不是文件属性**，必须实测才能断言 —— 在上述实测发生之前，任何把它说成「平台会替换」的句子都是没有依据的。

## 七、镜头语言词表（落在表外即 FAIL）

固定词表的理由：同一件事有多种写法时（「推镜」/「缓慢推进」/「慢推」），跨镜头的风格会**静默漂移**，
而漂移只在成片里看得见 —— 那时已经花过钱了。

- **景别**（`:236`）：特写 近景 中景 中近景 全景 远景 大远景
- **构图**（`:237`）：中心构图 三分法构图 对称构图 对角线构图 框架式构图 黄金分割构图 留白构图
- **运镜**（`:238`）：固定镜头 缓慢推进 快速推进 缓慢拉远 缓慢左摇 缓慢右摇 跟随侧移 缓慢上升 缓慢下降 环绕

要加新值就改 `script-gate.mjs` 里的 `SHOT_SIZES` / `COMPOSITIONS` / `CAMERA_MOVES`，
**改了就是一次有记录的决策**，而不是在某一集里顺手写一个新词。

## 八、时长与实测单价的硬约束

`时长` 不是自由值 —— 它必须落在**有实测单价**的档位里，否则闸门 E3 直接拒绝（**不外推**）：

| 已实测组合 | 算力 | 证据强度 |
| --- | --- | --- |
| `720p 5s` | 70 | 三条独立证据 |
| `720p 10s` | 140 | 画布 `node quote` |
| `720p 30s` | 600 | 画布 `node quote` |
| `1080p 15s` | 960 | 实测，但未在短剧链路验证 |
| `1080p 30s` | 1920 | 同上 |

这五个档位与 `script-gate.mjs:60-66` 的 `MEASURED_CREDITS` 表**逐条一致**（那是代码里的权威）。
**未实测的组合一律拒绝，不许外推。** 本工作台在 1080p/30s 上外推过一次：估了 630，真实 1920，**差 3 倍**。

⚠️ **这张表缺一个维度，读的时候要补上：模型。** 单价是「模型 × 分辨率 × 时长」的函数，
而 `MEASURED_CREDITS` 的 key 里没有模型。据 `cost-gate`（`C:\Users\曦曦\.dsh\.agent-presets\dsh-aivideo\skills\cost-gate\SKILL.md`
第 93–106 行的阶梯表）**推断**：`720p 5s = 70` / `720p 10s = 140` 是 `seedance_2.0_vip`，
而 `720p 30s = 600` **只能是 `seedance_2.5`** —— 因为同一份表记着 `2.0vip` 的单次上限是 15 秒
（30 秒被拒 `service.2`）。**要推翻这条推断**，用 `node quote` 对 `2.0vip` 与 `2.5` 各报一次 720p/30s 即可；
在那之前，报价时必须**同时说清模型、分辨率、时长**，只说时长会得到错误价格。

## 九、从本地 28 列到平台导入列

**不要手工转换。** 转换是一次纯机械的列映射，手工做只会引入错位；而错位不会报错，只会让某一列整体错开。

### 10.1 本 preset 的闸门只剩一个范围，而且它不判分镜表

原来那三个范围（`episode` / `series` / `cross-episode`，底层是 `script-gate.mjs --format json`）

⚠️ **于是本 preset 的分镜表没有自动判据。** 全部形状判据（E1–E31）都住在 `script-gate.mjs` 里，
而那个脚本已经不在本 preset 的工具面上了。两条可走的路：

1. **回退到脚本**（读得懂输出，但要自己判断四态）：
   ```powershell
   node D:\AIVideo\tools\script-gate.mjs --series <剧目录> --episode <N>
   ```
   它仍在盘上、仍可运行。**看四态，不是看退出码**（下表）。
2. **人读**。第三节的逐列表 + 第十一节的自查清单就是为这条路写的。

| 态 | 含义 | 能不能当绿灯 |
| --- | --- | --- |
| `PASS` | 判完了，没有 FAIL 也没有 UNAVAILABLE | ✅ 仅对**它判过的那些检查**是绿灯 |
| `FAIL` | 判完了，确认不通过 | ❌ 逐条读，别只看条数 |
| `UNAVAILABLE` | **跑不了**（缺文件/缺目录），没判 | 🔴 **不是通过** |
| `CRASHED` | 脚本崩了，或**参数用错** | 🔴 **不是通过** |

⚠️ **闸门文档里的退出码 `4`（运行期异常）不可达**：全文件没有 `process.exit(4)`、没有 `return 4`（实测搜索，零命中），
唯一的 `try/catch` 只包 `parseArgs`。于是**崩溃与用法错误都是退出码 1，退出码分不开这两件事**。

⚠️ **读 `findings` 的两条纪律**：① 「标 `?` 的是**跑不了**，不是**通过**。」
② 「某个 code 没出现，**不等于它过了**：`E5`/`E6` 在圣经读不到时会**故意什么都不发**，由 `E0-输入完整性` 代言。」
（依据：`:1837` 的断言文本与 `:1829` 注释。）`findings` 是 **list，不是 map**：
`E24` 最多出现 3 次、`E11` 有 8 个发射点、`E9`/`E9a`/`E9b` 可为同一原因同时出现 —— **按 code 取首条会静默丢掉结论**。

### 10.2 顺序纪律

**在用户从平台带回读数之前，不许写分镜表。** 平台评估读的是正文；正文没被读过就往下走，
等于把一份没有外部读数的稿子变成 28 列 × N 集的、要花钱的形状。
