# 分镜表：唯一权威格式

分镜表是本工作台**最贵的文件**。理由不是它难写，而是它错了以后，代价在生成阶段**乘性放大**：
实测一个镜头要重拍 3–6 次，而 720p/10s 一次就是 140 算力（账号月产能 725）。
所以这份技能的第一原则是：**把错误挡在花钱之前**。

## 一、平台吃进去的到底是什么（实测，不是推断）

有戏AI 有**两条完全不同的导入路径**，格式要求也不同：

| 路径 | 载体 | 允许格式 | 分集/解析规则 |
| --- | --- | --- | --- |
| **① 剧本导入** | 纯文本 textarea，**无文件上传** | 粘贴文本 | 用 `第n章` 或 `第n集` 分割 |
| **② 导入分镜表** | **文件上传** | **只认 Excel `.xlsx` / `.xls`** | 按模板列解析 |

来源：平台前端构建产物 + 官方教程正文（两处印证）。原文：

> 请导入剧本，将为你自动分集（文本请用"第n章/集"分割）
> 剧本支持10万字以内，长剧本需要分集，**每一集必需控制在2000字以内**
> 剧本是按照指定的关键词 "章，集" 来分章节的：第1章（或者 第一章）/ 第1集（或者 第一集）
> **注意：不能混合使用**，比如在同一个剧本中，同时使用：第1章， 第2集 ，这样是不能分集的

⚠️ **这两条是本技能里唯一「平台上真的会拦你」的规则**，其余都是我们自己的纪律。
`script-gate.mjs` 的 E9 断言就是在本地先把这两条验一遍。

### 官方模板（已实测下载并解出真实列名）

三个模板在 `https://pubsto.fullpeace.cn/drama/`，**前两行是注释行，导入前必须删除，第 3 行才是表头**：

| 模板 | 列数 | 表头（第 3 行原文） |
| --- | --- | --- |
| `分镜模板_剧情_生图转视频.xlsx` | **15** | 镜头 镜头剧本 分镜号 景别 构图 运镜 光影 场景 站位 分镜描述 音效 对白 时长 镜头图片提示词 镜头视频提示词 |
| `分镜模板_剧情_参考生视频.xlsx` | **13** | 镜头 镜头剧本 分镜号 景别 构图 运镜 光影 场景 分镜描述 音效 对白 时长 镜头视频提示词 —— **删掉的是「站位」与「镜头图片提示词」两列**（`分镜描述` 在；这份模式本来就没有图片提示词列） |
| `分镜模板_旁白.xlsx` | **6** | 分镜号 分镜剧本 场景 对白 分镜图提示词 分镜视频提示词 |

⚠️ **这张表被改错过一次，而且改的方向是反的，所以留痕在这里。** 它先写成「删掉的是『站位』与『镜头图片提示词』」（**这句是对的**），随后被「更正」成「无『站位』『镜头图片提示词』、也删掉了『分镜描述』」——
**那次「更正」才是错的。** 权威不是这张表，是**解出来的 xlsx 本身**：实测 13 列里有 `分镜描述`，没有 `站位`、也没有 `镜头图片提示词`。
同族的 `tools\board-to-xlsx.mjs:59-60` 的表头数组写对了，只有本技能的前身写反了。
列名表错一格，导出的表就会整体错开一格 —— 而错位不会报错。

模板自己的说明（原文）：

> 使用方式一：导入分镜信息后系统生成提示词 —— 建议填写【必填字段（红色）】+【绿色字段（按需）】
> 使用方式二：直接导入图片和视频提示词 —— 建议填写【必填字段（红色）】+【蓝色字段】
> 参考主体格式为： **@[主体]**，例如，@[凌霄]，@[八卦炉]，@[兜率宫内-八卦炉区]

**我们采用「使用方式一」**：填分镜信息，让系统生成提示词。理由是那些提示词列里有平台自己的
Shot 语法与主体替换逻辑，我们自己拼只会更差；而**分镜信息的正确性恰恰是我们能静态校验的部分**。

## 二、本地 28 列（闸门吃的那张表）

路径：`products/<剧名>/storyboards/第NN集-分镜.csv`

**顺序自由，但一个都不能少；多一列就报错**（拼错的列名静默通过是最坏的一种通过）。

> **唯一权威是代码，不是这份文档。** 列清单是 `D:\AIVideo\tools\script-gate.mjs` 里的 `REQUIRED_COLUMNS`（本技能写作时位于 `:85-116`）。**要用它就去读它**，不要引用任何文档里的列数 —— 包括这一份。
>
> 本项目已经在这件事上漂移过：同一个数组是 **28** 列，而 `script-gate.mjs` 自己的注释写「吃 20 列」（`:28,33`）、`board-to-xlsx.mjs:3` 写「25 列」、本技能的前身也写 25；`PROJECT.md:541,906` 还专门记了一条「新加的 5 列还没进技能，**这一条必须先做**」。
> 三段的来历：20（引用自洽 + 本地质检）→ 25（+ 叙事结构组，D-14）→ **28**（+ P1/P2 判据组，D-20）。

分三组：**引用自洽组**（第 1–20 列）管「这堆字符串互不矛盾」；
**叙事结构组**（第 21–25 列）管「这一集是不是一个完整的故事单元」，来自外部方法论「工业五阶门控剧本引擎」（见第六节）；
**P1/P2 判据组**（第 26–28 列）把平台 P1 验收里那条**跨集链式条件**变成可判的（见 D-20）。

| # | 列名 | 必填 | 取值与约束 |
| --- | --- | --- | --- |
| 1 | `镜头` | 是 | 纯数字序号 |
| 2 | `镜头剧本` | 否 | 该镜头对应的一句剧本，**只为人读** |
| 3 | `分镜号` | 是 | 集内唯一，形如 `1-1`。重复即 E2 FAIL |
| 4 | `景别` | 是 | **必须在词表内**（见第五节） |
| 5 | `构图` | 是 | 同上 |
| 6 | `运镜` | 是 | 同上 |
| 7 | `光影` | 是 | 写光源方向与对比度，不写「氛围很好」 |
| 8 | `场景` | 是 | **必须等于 `bible/scenes.json` 里的 `name`**（不是 id） |
| 9 | `站位` | 是 | 谁在画面哪个位置、离某物多远 |
| 10 | `分镜描述` | 是 | 画面事实描述。**`@[X]` 引用写在这里** |
| 11 | `音效` | 否 | 无则写 `-` |
| 12 | `对白` | 否 | 格式 `角色名：台词` 或 `旁白：…`。无则留空（**不要写「无」**） |
| 13 | `时长` | 是 | 秒。**必须落在已实测单价的档位内** |
| 14 | `画面类型` | 是 | 见第三节 |
| 15 | `可作首帧` | 是 | 只能 `是` / `否` |
| 16 | `参考图` | 是 | `;` 分隔的**文件名**，须真实存在于 `assets/`，**不得以下划线开头** |
| 17 | `出场角色` | 条件 | `;` 分隔的**角色 id**（`C-01`），不是名字。`空镜` 时留空 |
| 18 | `动作主体` | 条件 | **单个角色 id**，且必须在本镜 `出场角色` 内 |
| 19 | `所持道具` | 否 | `;` 分隔的 `道具id>持有者id:动作`，如 `P-02>C-01:挥拍`。空镜写 `P-03>:-` |
| 20 | `音色` | 条件 | 有对白时必填，取值来自 `bible/voices.json` 的 `id`（`V-01`） |
| 21 | `镜头功能` | 是 | `铺垫` / `冲突` / `转折` —— **三幕位置的唯一来源**，E14 按它算时长占比 |
| 22 | `集尾卡点` | 是 | `是` / `否`。**每集恰好一个 `是`**，且它必须落在最后 20% 时长内（E15） |
| 23 | `对白类型` | 条件 | `对白` / `旁白` / 空。有台词时填 |
| 24 | `对白功能` | 条件 | `施压` / `掩饰` / `反击`。**有对白必须填**；无对白必须留空（E17） |
| 25 | `节拍` | 是 | `目标` / `阻碍` / `升级` / `转折` / `新局面` —— 五段每集至少各一次（E16） |

### 第 26–28 列（D-20 立项，E21–E23 判）

`变化维度` / `变化状态` / `主动性`。这三列**不在这张表里展开**，因为它们的取值与必填性由代码判定 —— 去读 `script-gate.mjs` 里的 `E21-变化声明` / `E22-变化链继承` / `E23-主动性证据`。
它们要解决的是另一类问题：平台 P1 验收要求「第2至10集每集除新增信息外，至少改变目标、关系、资源或风险中的一项，**并由下一集继承**」—— 那是**跨集**条件，单集闸门在设计上就看不到它（同 E19 的理由）。

### 叙事结构组这 5 列解决什么

**没有它们，闸门只能判「这堆字符串互不矛盾」，判不了「这一集是不是一个完整的故事单元」。**
而这正是本工作台最贵的一种错：片子看起来没问题，播出去没人看完 —— **那不是语法错，是结构错**。

| 列 | 它让什么东西可判定 |
| --- | --- |
| `镜头功能` | 三幕比例（30/50/20%）与「每一幕非空」 |
| `集尾卡点` | 钩子是否真的落在尾部（而不是随便哪一镜） |
| `节拍` | 因果链五段是否齐；同一段有没有被灌水拉长 |
| `对白功能` | 对话有没有权力/信息的攻防变化（而不是「毫无立场的解释性闲聊」） |
| `对白类型` | 对白密度的口径（对白 vs 旁白）；也是走向「旁白解说模式」时的预留 |

⚠️ **这 5 列整列为空时，E13–E18 一律报 UNAVAILABLE**，不是 PASS ——
「读不到」与「没问题」必须区分（见 `script-delivery` 技能）。

### 三列是**特意分开**的，不要合并

`出场角色` / `动作主体` / `所持道具` 分成三列，是为了让下面这类错**静态可拒绝**：

> sample-001 的镜头 3 是「挥拍击球」，引用的却是**球**的资产。
> 两个画布节点都叫「生成物品三视图」，**靠标题永远区分不出来**，只有看图才发现。

拆开之后，闸门能断言「持有者必须在本镜出场角色内」且「动作必须在该道具的 `allowedActions` 内」。
合并成一列「道具：球拍（挥拍）」就退化成散文，机器判不了。

## 三、`画面类型` 的取值与它挡住的那类错

| 取值 | 含义 | 要求 |
| --- | --- | --- |
| `角色三视图` | 圣经里的角色素材 | 至少一个出场角色 |
| `物品三视图` | 圣经里的道具素材 | 同上 |
| `场景俯视图` / `场景图` | 圣经里的场景素材 | 同上 |
| `首帧图` | 某个镜头的生成输入 | 至少一张可解析的参考图 |
| `空镜` | **没有角色**的画面（只有物件/环境） | 出场角色必须为空、对白必须为空 |
| `联络表` / `拼图` / `QC报告` | **产物**，不是素材 | **一律拒绝作为生成输入** |

最后一类存在的原因是一次实测事故：

> QC 生成的联络表 `_contact-sheet.png` 是 **1480×744 的横向拼图**，被「取最新文件」逻辑
> 当成了首帧，导致输出 **960×960（1:1）** 而不是 9:16。
> **缺陷在选图逻辑，不在生成服务** —— 但它伪装成「服务不遵守比例」。

所以本工作台有一条硬纪律：**永不「取最新文件」**。素材只认「参考图」列里显式声明的文件名。

## 四、`@[主体]` 引用（平台自己的语法）

`@[X]` 里的 X 是**主体名**，不是 id。合法的主体名来自三张圣经表的 `name` 字段：

- `bible/characters.json` → 角色名（`沈金枝`、`陆砚`…）
- `bible/props.json` → 道具名（`剔骨刀`、`玉佩`…）
- `bible/scenes.json` → 场景名（`陆宅-正厅`…）

闸门 E7 会把每一个 `@[X]` 拿去主语表里查，查不到就 FAIL。
这条的价值在于：**写错的主体名平台不会报错，只会让画面漂** —— 那是花钱之后才发现的事。

⚠️ **已知边界（不要越界声称）**：我们只验证 `分镜描述` 里的 `@[X]`。
官方模板自身在**提示词列**里的示例（`背景是@[兜率宫内-八卦炉区]`）用的是同一套语法，
但平台在「使用方式一」下**是否也对我们填的分镜信息做主体替换、替换范围到哪一列，我们没测过**。
这是平台行为，不是文件属性，必须实测才能断言。

## 五、镜头语言词表（落在表外即 FAIL）

固定词表的理由：同一件事有多种写法时（「推镜」/「缓慢推进」/「慢推」），跨镜头的风格会**静默漂移**，
而漂移只在成片里看得见 —— 那时已经花过钱了。

- **景别**：特写 近景 中景 中近景 全景 远景 大远景
- **构图**：中心构图 三分法构图 对称构图 对角线构图 框架式构图 黄金分割构图 留白构图
- **运镜**：固定镜头 缓慢推进 快速推进 缓慢拉远 缓慢左摇 缓慢右摇 跟随侧移 缓慢上升 缓慢下降 环绕

要加新值就改 `script-gate.mjs` 里的 `SHOT_SIZES` / `COMPOSITIONS` / `CAMERA_MOVES`，
**改了就是一次有记录的决策**，而不是在某一集里顺手写一个新词。

## 六、时长与单价的硬约束

`时长` 不是自由值 —— 它必须落在**有实测单价**的档位里，否则闸门 E3 直接拒绝（**不外推**）：

| 已实测组合 | 算力 | 证据强度 |
| --- | --- | --- |
| `720p 5s` | 70 | 三条独立证据 |
| `720p 10s` | 140 | 画布 `node quote`（**不是线性**：5–10 秒档折合 14 算力/秒，而 30 秒档实测 600 = **20** 算力/秒） |
| `720p 30s` | 600 | 画布 `node quote` |
| `1080p 15s` | 960 | 实测，但未在短剧链路验证 |
| `1080p 30s` | 1920 | 同上 |

**未实测的组合一律拒绝，不许外推。** 本工作台在 1080p/30s 上外推过一次：估了 630，真实 1920，差 3 倍。

## 七、从本地 28 列到平台 15 列（本地质检列与结构列都不导出）

**不要手工转换。** 转换是一次纯机械的列映射，手工做只会引入错位；而错位不会报错，只会让某一列整体错开。

| 本地列 | → 平台「剧情_生图转视频」15 列 | 处理 |
| --- | --- | --- |
| 镜头 / 镜头剧本 / 分镜号 | 同名列 | 照抄 |
| 景别 / 构图 / 运镜 / 光影 / 场景 / 站位 / 分镜描述 / 音效 / 对白 / 时长 | 同名列 | 照抄 |
| 出场角色 / 动作主体 / 所持道具 / 画面类型 / 可作首帧 / 参考图 / 音色 | — | **本地质检列，不导出** |
| — | 镜头图片提示词 / 镜头视频提示词 | **留空**，让平台按「使用方式一」生成 |

导出的 xlsx 必须：**删掉前两行注释**、第 3 行表头照抄官方模板、文件名与集号对应。

**这一步的工具是 `D:\AIVideo\tools\board-to-xlsx.mjs`，它已经存在。**
本技能的前身曾写「导出这一步的工具尚未写」—— **那句已过期**，工具在，`INVENTORY.md:36` 与盘上那 12 个 `第NN_15列_平台导入.xlsx` 都是它产的。
它以官方模板为底、只替换 `xl/worksheets/sheet1.xml`，并**回读自证**（断言第 1 行是平台表头、列数正确、注释行已删）。
⚠️ 它把模板目录**硬编码**成 `D:\AIVideo\research-youxi\templates`（`:30`）—— 移动那个目录会让它读不到模板**而不报错**，只在产出的 xlsx 上体现。
**仍然必须由人做的一步**：导入平台后**核对平台分出的镜头数 == 本地的行数**（工具末尾就打印这句话）。

## 八、写完分镜表之后必须做的事

```powershell
node D:\AIVideo\tools\script-gate.mjs --series <剧目录> --episode <N>
```

**看三件事，不是看退出码**：

1. **有没有 FAIL** —— 那是确认的问题。
2. **有没有 UNAVAILABLE** —— 那是**跑不了**，不是通过。缺素材就补素材，不要当成绿灯跳过。
3. **报价数字** —— 那是上限报价，需人工批准才能生成。

如果行数不齐（手写 CSV 最常见的错），用 `node D:\AIVideo\tools\board-pad.mjs <csv>` 补齐 ——
它**只补空字段**，行比表头长时直接拒绝（截断会静默丢数据）。
