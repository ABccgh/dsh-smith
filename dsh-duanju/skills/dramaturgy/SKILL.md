# 竖屏短剧编剧法

> **读之前先知道这一件事：本工作台现在没有在跑的剧。**
> 毕业照 / 金枝 / 家规 三个剧本已取消并**完全删除**（git `0ace833`，D-69，`DECISIONS.md:3011`）；
> `products\` 下只剩 `image-to-video` 与 `travel-promo`，两个都不是剧本。
> 盘上唯一完整的剧是测试夹具 `tools\_fixtures\series-min\`（**它带着金枝的残留数据，是故意的，不要去清理** ——
> 见 `drama-workspace` 技能）。
> **所以下文出现的《金枝》人物，全部是「历史上做过的那一部」的示例，不是你现在要写的剧。**
> 要开工，先和用户确认剧名与题材，再新建 `products\<剧名>\`。

写这份技能的目的：用户不会写剧本，而**编剧恰恰是语言模型最擅长、成本最低的一环**。
但短剧的约束与长片、与小说都不同，套用「三幕剧」会写出又慢又散的东西。
下面每一条约束都是**由形态决定的**，不是偏好。

## 一、形态决定的四条硬约束

先记住这四条，再谈结构。它们会否决很多看起来不错的想法。

1. **每集 ≤ 2000 字**（有戏AI 官方上限，实测原文）。折成中文对白+动作，大约是
   **60–90 秒的成片量**。所以「一集」不是一章小说，是一个**信息单元**。
2. **竖屏 9:16**。横向的场面、群像、大景别在竖屏里损失巨大。
   竖屏的优势是**脸、手、单个物件** —— 这也是为什么本工作台的镜头语言词表里
   特写/近景/中景是主力。
3. **单集成本按秒计**（720p 10 秒 = 140 算力，月产能 725）。
   **凭空多写一个镜头就是多花钱。** 剧本阶段就要想「这一镜能不能并进上一镜」。
4. **观众在地铁上、碎片时间看**。所以没有「铺垫期」——
   **第 3 秒决定他留不留**，第 1 集决定他追不追。

## 二、一句话钩子（写不出来就不要往下走）

钩子必须能塞进一句话，且这句话里必须有一个**具体的、可验证的悬念**。

| 差 | 为什么差 | 好 |
| --- | --- | --- |
| 「一个女人的复仇故事」 | 抽象，没有具体对象，无法验证 | 「她顶着一个死人的身份混进仇家后厨」 |
| 「家族恩怨」 | 没有主角的具体行动 | 「她要养大的小少爷，不是这家的血脉」 |
| 「穿越回民国」 | 设定不是钩子，事件才是 | 「她认得那双手 —— 十年前举刀的就是他」 |

**检验方法（可执行）**：把钩子读给一个不知道剧情的人听，然后问
「那你现在想知道什么？」。如果他答得出一个**具体问题**，钩子成立；
如果答「想知道后面怎么样了」，钩子不成立 —— 那是在描述类型，不是在制造悬念。

## 三、人物：给矛盾，不给形容词

一条人物设定如果去掉形容词就什么都不剩，它是没用的。
每写一个人物，必须能填完这一行：

```
  他/她要 ______，但 ______，所以只能 ______。
```

示例（**历史示例**：这是本工作台做过、后来整体删除的那一部《金枝》—— 拿它讲矛盾式怎么填，不是一部在跑的剧）：

| 人物 | 矛盾式 |
| --- | --- |
| 沈金枝 | 她要复仇，但**要护住的孩子就在仇人家里**，所以只能先弄清楚当年是谁下的令。 |
| 陆砚 | 他要真相，但**真相会毁掉家族**，所以只能等她先开口。 |
| 陆夫人 | 她偷换了孩子，但**正因如此她成了唯一真心护那孩子的人**，所以只能沉默十年。 |

**反派也要有矛盾**，否则他在竖屏里会变成一个纯功能件，观众会快进。
「他既真的悔了，也真的动过手」比「他是个坏人」强得多。

### 人物设定的另一半是**外观锚点**

剧本里写的每一句人物描述，最后都要变成提示词里**逐条写死**的东西（见 `bible/characters.json`）。
所以写的时候就要按可画的标准写：

- ✅ 「左手手背一道旧疤，从虎口延伸到腕骨上方约三寸」
- ❌ 「眼神里有一种说不出的哀伤」

后者画不出来，而且每个镜头会朝不同方向漂 —— **那正是跨镜头一致性崩塌的起点**。

### 故意不要写的东西也要写下来

《金枝》的小少爷**左臂不能有胎记**（第 3 集的钩子就靠这个）—— 同上，**历史示例**。
这类「必须缺失的特征」如果不写进人物设定，模型会热心地给你补上一个胎记，
然后第 3 集就不成立了。**在 `appearance` 里显式标注「不要写 X」**。

## 四、十二集结构（功能表，不是提纲）

短剧的分集不是把故事切十二段，而是**每集承担一个功能**。下表是已验证可用的一张功能表：

| 集 | 功能 | 该集必须做的事 |
| --- | --- | --- |
| 1 | **建立钩子** | 前 3 秒出冲突；本集内给出「她为何而来」的**明确答案**（不要吊着） |
| 2 | 给动机 | 前史。让观众理解第 1 集那个动作的原因 |
| 3 | **给最大信息差** | 抛出一个观众知道、剧中人不知道的事实 —— 这是追剧的燃料 |
| 4 | 制造危机 | 身份/关系受到直接威胁 |
| 5 | 关系转折 | 两个关键人物结盟或对立 |
| 6 | 推进主线 | 从「猜」进入「查」 |
| 7 | 兑现第 3 集的钩子 | 观众等了三集的答案在这里给（**必须给**，不许再拖） |
| 8 | 反转 | 一个此前不可见的设定被揭开 |
| 9 | 对峙 | 正面对上 |
| 10 | 情感高潮 | 代价被真正付出来 |
| 11 | 收束 | 真相逼近，最后一道门被推开 |
| 12 | 结局与留白 | 给结局，留一个可被第二季接住的尾 |

**前三集免费、第 4 集起付费**是常见形态。所以**付费卡点必须落在信息差未闭合的位置**，
而不是落在情节平稳处。本工作台的做法是在 `story.json` 的每集 `paywall` 字段里显式写出来。

## 五、写剧本的格式（平台真的会读它）

产出两个文件：

- `script/第NN集.md` —— **人读版**，可以带场景标题、镜头建议、注释
- `script/可导入-第NN集.txt` —— **平台版**，纯文本，规则见下

平台版的**硬规则**（官方原文，也是 `script-gate.mjs` 的 E9 断言）：

```
第1集
（正文）

第2集
（正文）
```

- 每集以 `第N集` 或 `第N章` 起头，**绝不能混用**（混用则平台不能分集）
- 集号从 1 开始且**连续**
- 单集 ≤ 2000 字，全文 ≤ 10 万字
- 集标记单独占一行

⚠️ **不要**在平台版里写「（此处转场）」「（此时音效渐强）」这类制作注释。
那是给人看的，进了平台会被当成正文。

## 六、写完一集之后的自查

- [ ] 前 3 秒有冲突或异常？（不是「介绍一下背景」）
- [ ] 这一集**给出了什么新信息**？（一集没给新信息 = 一集废了）
- [ ] 本集结尾的悬念，**能不能被下一集真的接住**？（接不住的悬念是欺骗）
- [ ] 台词有没有「说出来是为了让观众听懂」的痕迹？（那是解说，不是对白）
- [ ] 有没有哪一镜需要的东西**画不出来**？（抽象情绪、复杂群体动作）
- [ ] **这一集的非空白字数在 1 600–1 900 之间吗？读回文件数出来的，不是估的**（上限 2 000 字/集是**平台拒收线**；实测 2 526 字/全 12 集 → D 55.7，20 554 字 → A 82.6）
- [ ] 分集标记与全集**统一**吗？（`第N集` 或 `第N章`，不得混用；跑 `duanju_gate`，`range: 'script-only'` 是最快的一次）
- [ ] 用户读过并确认了吗？（**这是唯一有效的「故事好不好」检查**，闸门不管这个）
- [ ] 平台读数回来了吗？（**没回来就不许写分镜表** —— 见 `script-delivery`）

## 七、已知未验证（不要当成事实）

- 有戏AI 的「旁白模式（小说漫 / 动态漫）」模板列数是 6 列，与剧情模式完全不同。
  本工作台目前**只走剧情模式**；旁白模式的完整写法未实测。
- 平台的 `AI随机生成剧本` 与内置编剧 Agent 的实际产出质量**未评估**。
  它们是可选输入，不是我们的替代品 —— 但值得在拿到第一版样稿后对比一次。
- **超过 12 集的形态，本工作台没有实测读数。** 下面第四节那张十二集功能表是**已验证可用的**，
  但它是否线性扩展到几十集，**没有测过** —— 长剧的排法见 `episode-engineering`，那一份里凡是几十集的算术都标了「推断」。
- **单集成本口径不在本技能里**，因为「档位不构成报价」：平台的算力/分钟 档位横跨 **133 → 4420（33 倍）**，
  引用它做任何算术都是错的。实测档位（即梦）与报价纪律见 `shotlist` 与 `youxi-platform`。
