# 平台规则的缺口与冲突：怎么处理

## 〇、一句话原则

**没有出处的规则不许写下来；没测过的数字不许算出来。**

本工作台的记忆层与技能里**不许冻结平台的规则**（`drama-project-memory` 第一节）——
平台的评分口径、评级映射、闸门条件、表头列名都会变，冻结一份进去，下一次平台改动就把它变成谎话，
而且**没有任何检查会因此变红**。它们以**引用**的形式旅行：带出处（哪个前端产物、哪一行、什么时候读的）。

这份技能处理的是这句话背后的具体情形：**查不到**，和**两份来源互相矛盾**。

## 一、四种状态的严格区分

对一条平台规则，你只可能处在四种状态之一。**把它们混在一起是本工作台最贵的一类错。**

| 状态 | 你该写什么 | 你**不许**写什么 |
| --- | --- | --- |
| **读到了** | 逐字原文 + 出处（文件:行 / 前端产物 / 平台页面 + 读的时间） | 不许转述成自己的话而不留原文 |
| **读不到** | 「未测量」+ **说清为什么读不到**（没有登录态？没有账号？界面改版了？） | 不许用「大概是」「一般来说」补一个值 |
| **两份来源矛盾** | 两份都写下来，各自带出处，标出冲突 | 不许替平台挑一个（除非有一个来源是**代码**，见第三节） |
| **来源是用户转述** | 「本次读数为用户转述」+ 转述的时间与场合 | 不许升格成实测 |

**为什么这条不是文风问题。** 本工作台付过学费：一份**本地断言全绿**的剧本，平台判了 **D 55.7**
（D-17/D-18）。当时的错误不是「不知道平台怎么评分」，而是**把自己会的东西当成了平台会认的东西**。
「未测量」这四个字是**可行动的**：它告诉下一个会话「这里需要一次实测」，而一个编出来的阈值
会告诉它「这里已经测过了」—— 后者更贵，因为它让人不再去测。

## 二、查一条平台规则时的来源优先级

从高到低，**高优先级压过低优先级，但高优先级也要说明自己是哪一层**：

1. **平台的运行时产物**（前端 bundle、接口响应、页面原文）。这是平台**自己**的字节。
   读的时候记下「哪个产物、哪一段、什么时候」，因为前端会随发布变化。
2. **平台自己下载的官方文件**（例如分镜模板 xlsx）。它是平台产出的**文件**，比一句文档更硬；
   而它的字节可以用 sha256 固定下来（`duanju_template` 每次都会打印 sha256）。
3. **用户提供的导出件／截图**（例如评估报告的 zip 或 PDF）。**次级**：它是平台对**某一次运行**的输出，
   不是平台的规则；而且在本项目里还要标明它测的是**哪一版**（三个剧本版本的三次读数混用就是这个坑）。
4. **用户的口头转述**。可用，但必须标注，并且它**只能被当成读数，不能被当成规则**。
5. **本工作台的技能与记忆层**。**最低**，而且**只应该引用前四层**。
   技能里出现一个平台数字而没有出处，那个数字应该被删掉或补上出处。

> 一条推论：**如果一条平台规则只在本工作台的文档里存在，它就已经失去了权威。**
> 要么去第一层重读一次，要么标成未测量。

## 三、矛盾出现了怎么办：三条裁定路径

**路径 A —— 有一份来源是代码，代码赢。**
本工作台的脚本是**我们自己的**代码，不是平台的规则，所以它对**我们自己的契约**有绝对权威。
最典型的例子是列契约：`D:\AIVideo\tools\script-gate.mjs` 的 `REQUIRED_COLUMNS` 数组是 **28** 列，
而同一个文件里**三处说法不一致** —— 文件头 `:29` 写「吃 20 列」、`:34-35` 的自我订正也写 20、
HELP `:443` 打印「25 列表头」。**用 `duanju_contract`，它机械抽取数组并列出所有与数组不符的说法。**

**代码赢的适用范围要划清**：它裁的是「我们的闸门到底判几列」这种问题。
它**裁不了**「平台到底会不会接受这份导出件」—— 那是平台行为，不是文件属性。

**路径 B —— 有一件工具能当场读出来，读它。**
下面第三节的每一条冲突都配了一个裁定动作。**能读的就不要讨论。**

**路径 C —— 两边都是平台口径且读不到 → 报给用户，不要自己裁。**
平台侧的规则冲突、以及**项目侧的取舍**（比如 `paywall` 字段与 `monetization.freeEpisodes` 不一致）
都属于这一类。**报出来的形态**：两份读数并排、各自出处、你的影响分析、
以及「这需要你定，因为它改的是产品而不是文件」。用 `ask_user_question`，或者放进 `inbox_add`
（如果这个答案跨越整个回合）。

| 9 | **`@[主体]` 的替换范围** | 我们在 `分镜描述` 里用的 `@[X]` 会被校验 vs 平台在「使用方式一」下**是否**也对我们填的分镜信息做主体替换、替换到哪一列 | **未测量** —— 这是**平台行为，不是文件属性**，必须实测才能断言 |
| 10 | **发布门槛的条数** | 仓库版把「所有剧集**已生成**」当硬闸门 vs 平台源码只测 `episodeList.length > 0`（**存在**，不是生成状态） | **A** —— 仓库版**更严**，所以它不产生假绿；但引用时必须说清「这是仓库读数，不是平台判据」 |
| 11 | **`compliance_status` 的含义** | 平台自己的措辞是「未见可据此直接判定阻断的明确材料」 | **不是通过，也不是阻断，是没有结论**，而它比评级更硬（发布前置）。**不许把它读成通过** |
| 12 | **评级映射** | 平台前端：`>=95 S+ / >=90 S / >=85 A+ / >=80 A / >=70 B / >=60 C / 否则 D` | **引用而非冻结** —— 任何一次评级转述都要和这条映射对账（`E19b` 做的正是这件事），它对不上就是转述错了 |
| 13 | **三把尺子不可相减** | 有戏AI **0–100** 五维 ｜ 剧云 **0–100** 六维 ｜ PageOne **0–10** | **不许做任何跨尺子的差**（D-60/D-61）。**任何两个相减都是错的** |
| 14 | **算力/分钟档位** | 平台教程给的是 `133 / 255 / 400 / 500 / 3000 / 4420` 的**档位区间**，横跨 **33 倍** | **不构成任何报价依据** —— 这种场合说「未测量」，不要挑一个档位算出一个数 |

## 五、写下一个数字之前的四问

1. **它的出处是这四层里的哪一层？**（平台产物 / 平台文件 / 用户的导出件 / 用户转述）
   说不出层，就别说出来。
2. **它是一次读数还是一条规则？**（读数属于某一次运行，规则属于平台 —— 两者漏了会变成谎话）
3. **它测的是哪一版？** 本工作台有过三个版本的三次读数被混着比的事故。
4. **它有没有可能已经被推翻？** 如果是老读数，先看记忆层里有没有更新的那条；`E19b` 的自洽校验会告诉你转述有没有抄错。

四问过不去 → 写「**未测量**」，并写清**要拿什么才能测**（一次登录、一次导出、一次页面读数）。

## 六、自查清单

- [ ] 我引用的每条平台规则都带**出处**（文件:行 / 前端产物 / 平台页面 + 时间）？
- [ ] 我说「未测量」的地方，有没有说清**为什么**读不到、以及**什么能测出它**？
- [ ] 两处来源矛盾时，我是**并排列出**了两份读数，还是替平台挑了一个？
- [ ] 有一个来源是**代码**时，我让代码赢了吗？（列契约、退出码、硬编码路径）
- [ ] 两边都是平台口径时，我**报给用户**了吗，还是自己裁了？
- [ ] 我有没有把一个**读数**当成一条**规则**写进技能或记忆层？
- [ ] 我报的每个数字，都能指出它是哪一次实测的哪一行吗？
