# 从 28 列分镜表到平台可导入的 xlsx

**平台的分镜表导入只认 Excel。** 本地分镜表是 CSV，这一步以前是人工做的，而人工做**正是这套系统要消灭的错位来源** ——
列映射错一格不会报错，只会让某一列整体错开。本技能管这一步的**形状**。

来源：`D:\AIVideo\tools\board-to-xlsx.mjs:5-7`（原话：「有戏AI 的**分镜表导入只认 Excel**（前端校验
`application/vnd...sheet` 或 `/\.(xlsx|xls)$/i`），而本地的分镜表是 CSV」）。

## 一、三份官方模板，以及它们实测的样子

模板实测在 `D:\AIVideo\research-youxi\templates\`（4 个文件，本技能引用的每一列名都从这三个里解出来实测过）：

| 文件 | 字节 | 真实列数 |
| --- | --- | --- |
| `分镜模板_剧情_生图转视频.xlsx` | 13 471 | **15** |
| `分镜模板_剧情_参考生视频.xlsx` | 13 681 | **13** |
| `分镜模板_旁白.xlsx` | **11 909** | **6** |
| `shot_import.xlsx` | **11 909** | **6**（**与 `分镜模板_旁白.xlsx` 逐字节相同的同一份** —— 平台自己的下载文件名就是它；两个 11 909 B 是同一个数，不是巧合） |

### ⚠️ 读之前先回答一个问题：你读的是**模板**还是**导出件**？

**同一个问题（表头在第几行）在两边答案不同**，所以任何一句「表头在第 N 行」都必须先说清是哪一边：

| 读的是谁 | 表头在第几行 | 为什么 |
| --- | --- | --- |
| **官方模板** | **第 3 行** | 前两行是注释行 |
| **导出件** | **第 1 行** | 导出时前两行已被删除 |

第 1 行的原文就是这句（三份模板实测都有）：

> 注意事项：此模板的第1，2行是注释行，导入分镜模板前，请将前两行删除

第 2 行**最后一个单元格**写的是 **「导入分镜表前请删除此行」**。
**两处措辞不一样**，所以用「注意事项」这一个串去识别注释行**只能匹配到第 1 行**；要认第 2 行得用另一个串。

### 🔴 陷阱 1：忘记删前两行会在**平台上**失败，而本地没有任何东西拦你

它对本地所有断言都是**隐形**的 —— 文件是合法的 xlsx、列名是对的、行数是对的。
唯一的本地防线是 `board-to-xlsx.mjs` 自己的回读自证（`:319` 的 `stillHasComment` 就是为这条加的断言）。

### 🔴 陷阱 2：每份模板都有一个**尾随空字符串单元格**

**它存在，但存的是空字符串**（实测，三份都有，所以不是某一份的怪癖）。
于是数单元格得到 **16 / 14 / 7**，而真实列数是 **15 / 13 / 6**：

| 模板 | 第 3 行的单元格数（按 XML 元素） | 非空名字数 = 真实列数 | 尾随单元格 |
| --- | --- | --- | --- |
| `分镜模板_剧情_生图转视频.xlsx` | **16** | **15** | `P3=""` |
| `分镜模板_剧情_参考生视频.xlsx` | **14** | **13** | `N3=""` |
| `分镜模板_旁白.xlsx` | **7** | **6** | `G3=""` |

**不要被它骗的办法：数表头的「名字」，不要数单元格。** 这句话在本工作台已经被写错过一次，
所以值得说明白它错在哪：**「列数」这件事没有中间数** —— 它要么是 15，要么是 16，
而哪一个对取决于**下游是谁**。平台的模板定义按名字走，所以是 15。

### 三份模板的表头（第 3 行原文，逐字）

| 模板 | 表头 |
| --- | --- |
| 剧情_生图转视频（**15**） | 镜头 镜头剧本 分镜号 景别 构图 运镜 光影 场景 **站位** 分镜描述 音效 对白 时长 **镜头图片提示词** 镜头视频提示词 |
| 剧情_参考生视频（**13**） | 镜头 镜头剧本 分镜号 景别 构图 运镜 光影 场景 **分镜描述** 音效 对白 时长 镜头视频提示词 |
| 旁白（**6**） | 分镜号 分镜剧本 场景 对白 **分镜图提示词** 分镜视频提示词 |

三份的差异，逐条说清（这是最容易记错的地方）：

1. **`参考生视频` 没有 `站位`，也没有 `镜头图片提示词`；它有 `分镜描述`。**
   ⚠️ **这条被改错过一次，而且改的方向是反的，所以留痕在这里。** 它先写成「删掉的是『站位』与『镜头图片提示词』」
   （**这句是对的**），随后被「更正」成「也删掉了『分镜描述』」——**那次「更正」才是错的**。
   权威不是任何一张表，是**解出来的 xlsx**。`script-gate.mjs:22-26` 把这件事故记在了代码里，
   `board-to-xlsx.mjs:60` 的表头数组写对了。**列名表错一格，导出的表就会整体错开一格 —— 而错位不会报错。**
2. **`参考生视频` 只比 `生图转视频` 少两列，而少的那两列不是相邻的。** 少的是第 9 列 `站位`
   与第 14 列 `镜头图片提示词` —— 所以**不能用「删掉末尾 N 列」的方式在两者之间转换**，
   中间那一列 `时长` 的位置两边不同。
3. **旁白模板没有 `时长` 列** —— 旁白模式下的时长只能由平台决定。
4. **旁白模板的列名是 `分镜图提示词`，不是 `镜头图片提示词`** —— **差一个字符**
   （「分镜图」vs「镜头图片」）。用字符串相等去匹配、或按「剧情」列名去对照，都会**静默失败**。
5. 旁白模板有 `分镜剧本`（不是 `镜头剧本`），**也差一个字符**。同族陷阱。

## 二、平台自己的语法与「两种使用方式」

**模板正文原文**：`参考主体格式为：@[主体]，例如，@[凌霄]，@[八卦炉]，@[兜率宫内-八卦炉区]`。

模板给出两种使用方式：

- **使用方式一：导入分镜信息后系统生成提示词。** 建议填写【必填字段（红色）】+【绿色字段（按需，「分镜描述」建议必填）】，
  导入后点「生成故事板」，系统为 15 列里的两个提示词列生成内容。
- **使用方式二：直接导入图片和视频提示词。** 建议填写【必填字段】+【蓝色字段（图片和视频提示词）】，
  导入后直接看「故事板」Tab。

**本工作台采用「使用方式一」**：填分镜信息，让系统生成提示词。理由是那些提示词列里有平台自己的
Shot 语法与主体替换逻辑，我们自己拼只会更差；而**分镜信息的正确性恰恰是我们能静态校验的部分**。
所以导出时 `镜头图片提示词` / `镜头视频提示词` **留空**。

## 三、导出的工具：`board-to-xlsx.mjs`（已存在，本 preset 不提供）

```powershell

# 真导出
node D:\AIVideo\tools\board-to-xlsx.mjs --series <剧目录> --episode <N> [--out <文件>] [--mode <模板名>]
```

实测行为（**逐条来自该文件本身**，不是推断）：

| 项 | 实测 |
| --- | --- |
| `--mode` 可取值 | `剧情_生图转视频`（**默认**）/ `剧情_参考生视频` —— **只有两个**（`:36-77` 的 `TEMPLATES`） |
| ⚠️ 旁白模式 | **没有第三个模板。** `--mode 旁白` 会报「没有这个模板」并退出 1（`:213`）。**旁白路线这一步没有工具。** |
| 输出路径默认值 | `storyboards\第NN_<列数>列_平台导入.xlsx`（`:291`，文件名里带列数，所以 15 列与 13 列**不会互相覆盖**） |
| 目标模板目录 | **硬编码** `D:\AIVideo\research-youxi\templates`（`:30`） |
| 缺映射列 | **报错退出 1**，不静默留空（`:240-244`） |
| 退出码 | `0` 成功 / `1` 用法或输入错 / `2` **导出后回读自证失败** / `3` 模板缺失（`:184`） |

### 它怎么工作，以及为什么这样设计

以**官方模板为底**：解模板 zip → **只替换** `xl/worksheets/sheet1.xml` → 重新打包。
模板自带的一切（样式、列宽、数据校验）原样保留；从零造一个 xlsx 会丢掉这些，而平台的行为可能因此不同。
数据用 inline string 写，不动 `sharedStrings.xml`（改动面越小，出错面越小）。

### 回读自证：它自证什么、不自证什么

导出后它**重新解出自己写的文件**并断言（`:301-330`）：第 1 行是平台表头、**逐字**相符、列数正确、
总行数 = 1 + 数据行数、第 1 行**不含**注释文字。

⚠️ **这份自证是对它自己的文件做的，不是对平台做的。** 它证明「我按模板的列名写对了」，
**不证明「平台一定会接受」**。`platforms\youxi\README.md:31-34` 把这句限度写得很直白：

> **`templates/` 的存在不等于「平台一定会接受我们导出的 xlsx」。**

### 🔴 唯一必须由人做的一步

工具末尾自己会打印这句话（`:332`）：

> ⚠️ 下一步必须人工做：导入平台后**核对平台分出的镜头数 == 本地的 N 行**。
> 数量不符就是列映射或格式有问题，不是「平台偶尔出错」。

**这一步没有自动化替代** —— 本机没有该平台的登录态，也没有它的 API。

## 四、它会读错的地方：两处**陈旧数字**，别把它们当契约

`board-to-xlsx.mjs` 自己也有落后于列契约的描述，引用前先知道：

- `:3` 与 `:177` 写「本地 **25 列**分镜表」—— **陈旧**。本地契约是 **28** 列
  （权威是 `script-gate.mjs` 的 `REQUIRED_COLUMNS` 数组字面量，见 `shotlist` 技能第二节）。
- 但它**不校验本地列数**：它只检查「映射表里提到的本地列是否存在」（`:240`）。
  所以**一份 25 列的旧表它会照常导出、不报错** —— 少的那三列（第 26–28 列）本来也不导出，
  于是**这次导出是对的，而那份表是过期的**。区分这两件事：导出成功不代表输入合规。
