# 投稿与发行：闸门、条件、以及一个没有结论的阻塞项

**平台侧的动作全部由人在网页上完成** —— 有戏AI 没有 CLI、没有公开 API，本机也没有它的凭证
（实测：全树递归搜 `.env*`/`*token*`/`*cookie*`/`*credential*`/`*secret*` → 0 个文件）。
所以本技能的作用是**在用户点那个按钮之前，把该满足的条件讲清楚**，以及**把平台给出的读数读对**。

⚠️ **两件事必须分清，本工作台为混淆它们付过学费**：

| | 判什么 | 谁判 |
| --- | --- | --- |
| **本地闸门**（`script-gate.mjs` 的 E1–E31） | **手艺**：对白密度、三幕比例、节拍、引用合法性 | 我们自己的代码 |
| **平台评估**（剧本评估） | **内容**：评级与五维打分 | 平台 |

`PROJECT.md:976` 记着那次教训：**闸门 18 PASS / 0 FAIL 而平台判 D，两者不矛盾。**
**「0 FAIL」不构成任何关于质量的证据。**

## 一、发布闸门：**六条**，逐字来自平台前端源码

出处：`D:\AIVideo\research-youxi\chunks\index-BITPFwMb.js`（平台前端主包）里发布函数的顺序判断。
六条按代码顺序，每条都是**一句平台原文 + 一个早退**：

| # | 条件（源码里的判断） | 平台原文 | 漏了会怎样 |
| --- | --- | --- | --- |
| 1 | 该剧本**尚未提交过发布** | 「该剧本已提交发布，请勿重复提交」 | 提示并中止 |
| 2 | `episodeList.length >= 10` | 「**剧集少于10集，不能发布**」 | 提示并中止 |
| 3 | `episodeList.length > 0` | 「请先生成剧集，或者先评估剧本」 | 提示并中止 |
| 4 | `creationDetail?.review_status === "completed"` | 「请先生成剧集后再发布」 | 提示并中止 |
| 5 | 上一条不成立时 | 「**请先评估剧本后再发布**」 | 提示并中止 |
| 6 | 评级 ∈ `["S+","S","A+","A"]` | 「**只能发布A级以上评级的剧本**」 | 提示并中止，且清掉读数 |

**第 6 条的权威原文**（`DECISIONS.md:3152` 逐字记着，同一串也出现在平台前端里）：

```js
if (!['S+','S','A+','A'].includes(grade)) { warning('只能发布A级以上评级的剧本'); return }
```

⚠️ **一个容易读错的地方**：平台前端知道 **8 个**评级字符串 ——
`["S+","S","A+","A","B+","B","C","D"]`；而**能发布的是前 4 个**。
所以「B+ 是一个合法评级」与「B+ 能发布」是两句不同的话，**第二句是错的**。

⚠️ **评级是**算**出来的，不只是读出来的**：源码在 `overview.grade` 缺失时用 `overall_score` 反推
（≥95 → `S+`，≥90 → `S`，≥85 → `A+`，≥80 → `A`，≥70 → `B`，≥60 → `C`，否则 `D`）。
**所以「总分 82.6」与「评级 A」是同一件事的两种表示，不是两个独立读数。**

### 本地的对应物：`E19-发布门槛`

`script-gate.mjs` 有一条系列级判据 `E19` 去逼近上面第 2 条，**但它只报本地可查的部分**（`:721-731`）：

- 本地能判：`story.json` 声明的集数 ≥10、`storyboards/` 下的分镜表份数 ≥ 声明集数。
- 本地判不了：`review_status`、评级、剧集是否真的已生成。

⚠️ 而且它自己写着一条**措辞纪律**（`:703-705`）：源码的条件只有 `episodeList.length > 0`，
即**剧集存在**，不是「已生成」；**「所有剧集已生成」是本仓库的读法，它比平台更严。**
方向重要：**更严不会产生假绿**，但引用时要说清它是仓库读数。

⚠️ **本 preset 现在没有闸门工具**（`duanju_gate` 只跑 `range: "script-only"`）。
`E19` 仍在 `script-gate.mjs` 里，回退到脚本才能跑到：

```powershell
node D:\AIVideo\tools\script-gate.mjs --series <剧目录> --series-check
```

## 二、发布投稿**表单**自己的五个条件

这是**另一组**条件，与第一节的六条不是同一件事：第一节是「能不能进入发布流程」，
这一组是「点提交时表单本身还要什么」。出处：同一批前端包里的投稿弹窗提交函数。

| # | 字段 | 条件（源码原文） |
| --- | --- | --- |
| 1 | `hook`（一句话卖点） | 「请填写一句话卖点（**至少5字**）」 |
| 2 | `synopsis`（剧本简介） | 「请填写剧本简介（**至少10字**）」 |
| 3 | `target_audience`（目标受众） | 「请填写目标受众」—— **非空即可，源码不给长度门槛** |
| 4 | `price`（售价） | 「请输入有效的售价」—— 判据是 `Number(price) > 0` |
| 5 | 封面 | 「请上传封面」或「请先生成AI封面」—— 二选一，取决于上传/生成哪条路 |

**提交体的字段名**（源码原文，读读数或对接时按这个拼）：
`title` / `core_selling_point` / `overall_comment` / `audience_profile` / `gold_coin` / `tags` / `cover_item_id`。

**第 1、2 条的初值是平台从评估报告里填的**（同一批源码）：
`hook` ← `reportJson.overview.core_selling_point`，`synopsis` ← `overview.overall_comment_md`，
`target_audience` ← `overview.audience_profile_md`，`tags` ← `overview.selling_tags`（**截前 8 个**）。
**所以评估报告写得越具体，这一页要补的越少** —— 这也是「评估不只是拿一个分数」的理由。

## 三、发行申报的待补全清单（十二项 + 一条进度条件）

这是**第三条路**，与第一节的剧本发布不同：`/dramaDistribution` 是「上传全集 + 版权证明，平台托管发行，按分成结算」。
出处：`D:\AIVideo\research-youxi\chunks\dramaDistributionSubmit-CU37ZZZS.js` 里申报页的预提交检查函数 ——
它把每一项缺失 `push` 成一条待办，**列表非空就是「待补全」**。

12 项，逐字：

1. 缺少剧集名称，请补充
2. 缺少剧集介绍，请补充
3. 缺少导演信息，请补充
4. 缺少制片人信息，请补充
5. 缺少题材信息，请补充
6. 缺少主创联系方式，请补充
7. 缺少全集链接，请补充
8. 缺少发行封面，请上传
9. 缺少版权信息，请补充
10. 缺少集数，请补充
11. 缺少时长，请补充
12. **剧情尚未完结，进度未达100%** —— 原文「完成全部集数后再提交」

⚠️ **第 12 条有一个代码层面的边界，值得写下来**：它的判据是
「`progress` 字段存在 **且** < 100」才报缺。**`progress` 不存在时这一条不触发** ——
**「检查没触发」与「检查通过」在这里又一次长得一样。** 不要把它读成「进度没问题」。

**第 9 条「版权信息」有平台给出的选项清单**（源码原文，5 项）：
`4张后期制作工程文件（如剪辑、特效图层工程等）` / `可信时间戳认证证书` / `剧本采买合同` /
`视听作品的版权登记证书` / `文字作品的版权登记证书`。
**这是一选清单，不是全交清单** —— 源码把它渲染成可选项。

**正片全集的三条硬条件**（同一文件里的界面文案原文）：

> 要求一次性上传全集。视频分辨率**不低于 720p**，单集**最好不超过 500 MB**。
> 文件命名：**剧名-对应集数**，比如：我的中国心-第1集。可补充正片网盘链接。

⚠️ **注意措辞的不对称**：分辨率是「**不低于**」（硬），单集体积是「**最好**不超过」（软）。
**不要把「最好」引成「必须」。** 初审时限也在这段文案里：「预计 **1-3 个工作日**完成初审」。

## 四、`compliance_status` 是唯一没有结论的阻塞项

平台评估报告里有一个 `market_fit` 对象，装两个字段：`compliance_status` 与 `popularity_status`。

**`compliance_status` 在两次平台读数里都是「未知」**（`PROJECT.md:638`、`:870`、`:959`、`:1064`，
`DECISIONS.md:1017`、`:1900`、`:2162`、`:2245`）。平台自己给的原因是：

> 未见可据此直接判定阻断的明确材料

### 🔴 这**不是通过**。它是**没有结论**。

三种状态必须分开写、分开读：

| 状态 | 含义 | 能不能投稿 |
| --- | --- | --- |
| 通过 | 平台给了合规结论 | 可以 |
| 阻断 | 平台说了不能做 | 不可以 |
| **未知** | **平台没给结论** | **不知道 —— 这正是它成为阻塞项的原因** |

**它是发布门槛之外唯一还没落地的条件**（`PROJECT.md:639`）。而且它是**平台侧的事实**，
本地任何检查都判不了 —— `script-gate.mjs` 的 `E19b` 只校验读数**内部自洽**，`script-gate.mjs:744` 明写：
**「它不断言评级高低，只断言读数内部一致。」**

### 一条同样重要的性质（`DECISIONS.md:2245`）

> **`compliance_status` 不是剧的属性，是「平台这次拿到了什么材料」的函数。**

所以「上一次是未知」**不构成**「这一次也会是未知」的证据 —— 它是可以靠补材料改变的东西。
`platforms\youxi\README.md:60-61` 的请求很具体：**如果你有它的定义、取值或判定方式，那是最有价值的一份资料。**

### ⚠️ 本技能找不到的一个东西，写在这里免得下一个人重找

**「发行评估」这个词在平台产物与工作台记录里都不存在。** 我实测搜过
`research-youxi\chunks\*.js`、`research-youxi\index-Cpt08ad5.js`、`research-youxi\feishu-share.txt`、
`PROJECT.md`、`DECISIONS.md`、`INVENTORY.md` —— **6 个文件，0 命中**。

**已知存在的评估只有一种**：平台的**剧本评估** —— 它读**正文**，产出评级与五维分数，
写进 `评估报告-回填.json`；**它发生在分镜表存在之前**（`script-gate.mjs:744-745`：
「评级是平台对**内容**的判决，E1–E29 判的是**手艺**」）。

**发行侧的对应物是「发行申报」**（第三节那 12 项），它是**表单门槛**，不是评级评估。
`DECISIONS.md:265` 另记着托管发行的五步里含一步「平台审核评估（内容质量/制作完成度/题材适配度/版权清晰度）」——
**那是一份转述，不是平台原文**，而且它不给分数。

**推断（标明）**：「发行评估」可能指的就是上面那一步，也可能是我的检索没覆盖到的一份材料。
**要把它变成实测**：在平台上走一次发行申报，看它是否给出一份带分数的评估报告；
或者找到那份含「发行评估」字样的平台原文。**在那之前，不要引用这个词，也不要为它设一个阈值。**

## 五、读平台读数时的四条纪律

1. **读数来源一律标注。** 本机没有平台登录态，读数通常是**用户在会话里的转述**。
   `duanju_recall` 校验的只是**自洽性**（顶层副本与 `readings[]` 末条一致、`grade` 与总分映射一致、
   五维 id 顺序与均分 ×10），**它抓不出「整份报告读错」**。所以写「本次读数为用户转述」，
   **不要升格成实测**。
2. **不许预测评级。** 平台只给分、不给新的诊断文字时，如实说「这一次没有诊断，所以『还差在哪』没有权威答案」。
3. **平台改完不会自动重评。** ⚠️ 但这句**没有平台产物作为出处** —— 它是工作台记录里的说法
   （`DECISIONS.md:2220,2309`、`PROJECT.md:61,422,759,951`），本机读不到那个界面。
   **按它行动（改完让用户再点一次评估）是对的；说「平台规定不会自动重评」是错的。**
   要把它变成实测：改掉 textarea 里的正文，不点评估，看已有分数动不动。
4. **`E19b` 没跑 ≠ 通过。** 缺 `评估报告-回填.json` 时它报
   「**这不是通过，是这条判据没跑**」（`script-gate.mjs:751-752`）—— 这个行为是对的，引用时连这句话一起带上。

## 六、自查清单

- [ ] 分清**本地闸门**（手艺）与**平台评估**（内容）；不把「0 FAIL」说成质量证据
- [ ] 发布六条闸门逐条对过，**评级必须在 `S+/S/A+/A` 之内**（B+ 合法但**不能发布**）
- [ ] 投稿表单五项：卖点 ≥5 字、简介 ≥10 字、目标受众非空、售价 >0、封面已上传或已生成
- [ ] 发行申报：12 项待补全逐条对过；**第 12 条（进度 100%）在 `progress` 缺失时不触发 —— 不触发 ≠ 通过**
- [ ] 正片全集：分辨率**不低于** 720p（硬）、单集**最好**不超过 500 MB（软）、命名 `剧名-第N集`
- [ ] `compliance_status` 如果仍是「未知」，**写成「没有结论」，不写成通过也不写成阻断**
- [ ] 每一条读数写清是**用户转述**还是实测
- [ ] 不发明阈值、价格、评分或平台规则；引用平台原话时带上出处
