# 六个剧本域工具：参数、输出、以及边界

这六个工具由一个**宿主平面的 Cordis 插件**注册（源码 `D:\dsh-duanju-script\`，包名 `dsh-duanju-script`）。
它们把工作台里原本要肉眼解析的脚本输出变成**结构化读数**。

> **它们不是本工作台的工具链本身。** 权威仍然是 `D:\AIVideo\tools\` 下的脚本 ——
> `duanju_gate` **一条检查都不重实现**，它只是跑 `script-gate.mjs --format json` 并把 `findings[]` 原样透出。
> 所以「工具报了 PASS」与「闸门报了 PASS」是同一件事，而「工具报不出来了」有它自己的含义（见第三节）。

## 一、精确参数表

| 工具 | 参数 | 必填 | 返回值 |
| --- | --- | --- | --- |
| `duanju_gate` | `series`（剧目录绝对路径） | ✅ | 一份结构化闸门报告（见第二节） |
| | `range` ∈ `episode` / `series` / `cross-episode` / `script-only` | ✅ | |
| | `episode`（数字） | `range=episode` 时需要 | |
| | `assetsDir` / `qcDir`（绝对路径） | 否，覆盖参考图目录与首帧 QC 目录 | |
| `duanju_contract` | `series`（剧目录绝对路径） | 否；给了就额外对照这部剧的 `storyboards\第NN集-分镜.csv` | 列契约三段对照 |
| `duanju_board` | `series` | ✅ | 逐表形状判定 |
| | `episode`（数字） | 否，省略=全部 | |
| `duanju_template` | `template`（模板文件名，例如 `分镜模板_剧情_生图转视频.xlsx`） | ✅ | 模板字节读 + 基线比对 |
| | `compareWith`（一份导出件的绝对路径，`.xlsx` 或 `.csv`） | 否 | + 导出件对照 |
| `duanju_recall` | `series` | ✅ | 全剧状态投影 |
| | `backfillFrom`（读数文件位置覆盖） | 否，默认 `<剧目录>\评估报告-回填.json` | |
| `duanju_checkpoint` | `series` | ✅ | 受管区块写入报告 |
| | `dryRun`（布尔） | 否；`true` 只渲染不落盘 | |

**`range` 的四个值对应四条不同的闸门命令行**（这是 `duanju_gate` 替你拼的那段）：

| `range` | 实际跑的命令 | 输出方言 |
| --- | --- | --- |
| `episode` | `script-gate.mjs --series <dir> --episode <N> --format json` | JSON |
| `series` | `script-gate.mjs --series <dir> --series-check --format json` | JSON |
| `cross-episode` | `script-gate.mjs --series <dir> --cross-episode --format json` | JSON |
| `script-only` | **换脚本**：`script-only-check.mjs --series <dir>`（**它没有 json 模式**） | 文本 |

**两个方言（`rules.mjs:38-49`，插件自己的注释）**：`script-gate.mjs` 有 `--format json`；
`script-only-check.mjs` **没有** json 模式，只打人类可读的三态行（`? [UNAVAILABLE] …` / `✗ [FAIL] …` /
`✓ [PASS] …`，加一行 `汇总：…`），所以分类器为它单独走一条文本解析路径。

> **这条是插件的实现记录里最值得抄的一段，因为它是跑出来的**：最初的实现**只认 JSON**，
> 于是 `range=script-only` 的一次**完全正常**的运行（退出码 3 = 有 UNAVAILABLE）被报成 `CRASHED` ——
> **一个健康的东西被自己的分类器说成崩了**。四态设计的价值正好在这里：它没有安静地把它折成一个 `PASS`。

⚠️ `episode` 不给 `episode` 参数时，工具**不猜一个集号**，它直说「这不是通过，是这次调用没成形」。读到这句就去补参数，不要往下走。

## 二、四态：`PASS` / `FAIL` / `UNAVAILABLE` / `CRASHED`

`duanju_gate` 的报告以 `# 剧本闸门 · <态>` 开头，然后给出剧目录、范围、命令、退出码，再是汇总与逐条 `findings`。

| 态 | 含义 | 你能不能当成绿灯 |
| --- | --- | --- |
| `PASS` | 闸门判完了，没有 FAIL 也没有 UNAVAILABLE | ✅ 仅对**它判过的那些检查**是绿灯 |
| `FAIL` | 闸门判完了，确认不通过 | ❌ 逐条读，别只看条数 |
| `UNAVAILABLE` | **跑不了**（缺文件/缺目录），没判 | 🔴 **不是通过** |
| `CRASHED` | 脚本崩了，或**参数用错**（工具再分出一个 `USAGE` 变体，正文版式相同） | 🔴 **不是通过** |

**为什么有第四态，而不是三态。** 闸门自己的文档写着退出码 `4` = 运行期异常（`script-gate.mjs:441` 的 HELP，
以及 `:45` 的头注释），而那个码在代码里**不可达** —— 全文没有 `process.exit(4)`、没有 `return 4`，
唯一的 `try/catch` 只包 `parseArgs`。于是任何别处抛出都是一次未捕获异常 → 退出码 **`1`**，
而用法错误的退出码**也是 `1`**。**退出码分不开这两件事。**

所以 `duanju_gate` 的判据是：**stdout 能不能解析成 JSON**，加上 **stderr 里有没有「用法错误」**，
**不看退出码**。你也不需要自己判 —— 报告里那行「退出码：1」只是转述，`# 剧本闸门 · CRASHED` 才是结论。

**读 `findings` 的两条纪律（工具每次都会在末尾重印）：**

1. 「上面标 `?` 的是**跑不了**，不是**通过**。」 —— 那是 `UNAVAILABLE` 条目，与 `✗` 一样非零退出，但含义相反。
2. 「某个 code 没出现上面，**不等于它过了**：`E5`/`E6` 在圣经读不到时会**故意什么都不发**，由 `E0-输入完整性` 代言。」

`findings` 是 **list，不是 map**：`E24` 最多出现 3 次、`E11` 有 8 个发射点、`E9`/`E9a`/`E9b` 可为同一原因同时出现。
**按 code 取首条会静默丢掉结论** —— 按出现顺序整体读。

## 三、什么时候用工具，什么时候必须回到 `node`

**规则一句话：工具做得到的，用工具；做不到的，明确说「工具不做这个」再跑脚本。**

| 要做的事 | 用工具 | 工具**做不到**的部分 → 回到 `node` |
| --- | --- | --- |
| 跑闸门拿四态 | `duanju_gate` | 无需回退；四个 `range` 就是全部范围 |
| 查列契约 | `duanju_contract` | 无需回退 |
| 分镜表形状（列契约/参差行/分镜号唯一/时长合计） | `duanju_board` | 补空字段要 `board-pad.mjs`；更细的行形状诊断可 `diagnose-board.mjs` |
| 官方模板字节对照 | `duanju_template` | 无需回退 |
| 一个剧的当前状态 | `duanju_recall` | **写**受管区块之外的任何东西都不在它范围内 |
| 写 `项目总览.md` 受管区块 | `duanju_checkpoint` | **没有回退** —— 手写会破坏受管区块 |
| 从一份 JSON 源生成正文与分镜表 | ❌ 不做 | `episode-build.mjs`（`--all` / `--all --script` / `--check` / `--import`） |
| 导出平台可导入的 xlsx | ❌ 不做 | `board-to-xlsx.mjs`（先 `--dry-run`） |
| 用另一个 zip 读取器独立复核 xlsx | ❌ 不做 | `verify-xlsx-external.mjs` |
| 钩子审计、素材台账、产能核对 | ❌ 不做 | `hook-audit.mjs` / `asset-manifest.mjs` / `quota-check.mjs` |

**为什么这个边界是刻意的，而不是缺功能。** `script-only-check.mjs` 就是 E9/E28/E29 的第二份实现，
两份只能手工同步 —— 而它自己的文件头就写着「权威是 script-gate」。所以 `duanju_gate` 的 `script-only`
范围是**转调它**而不是重写它，六个工具里**没有任何一条检查被重新实现**。多一份实现就多一个漂移面。

## 四、每个工具的输出形状（读之前先知道该找什么）

**`duanju_contract`** — 五段：权威路径与抽取方式 → `列数：**28**` → 列名（按数组顺序） → ① 闸门源码里的「N 列」说法（只列**与数组不符**的） → ② 官方模板的实测列矩阵（每份一个 sha256 前缀比对） → ③ 本地分镜表对照（只在给了 `series` 时跑；没给时它会明说「这一节没跑，**不是通过**」）。
它末尾自己声明两件不做的事：**不改任何文档**（文档里的数字漂移由代码判定谁对，修文档是人的决定），
以及**不证明平台会接受你的导出件**。

> 抽不到 `REQUIRED_COLUMNS` 数组时它**抛错，绝不返回空数组** —— 空数组会被下游读成「没有列要求」。

**`duanju_board`** — 每张表一段：`表头 N 列 · 数据 M 行`，然后是列名/列数对照、`分镜号` 重复、`镜头` 非数字、
`时长` 合计与 `story.json` 声明值的差。最后一行是它自己的边界：
**「本工具判的是形状。它不判内容：钩子好不好、节奏对不对、平台会不会满意 —— 那三件都不在这里。」**
没有匹配的 CSV 时它说的是「**这不是「没有问题」，是这些表不在**」。

**`duanju_template`** — 语料路径 + 字节数 + `sha256` → 逐行 `cellPreview`（`∅` 表示空串单元格）
→ 与基线的比对 → 可选的导出件对照。给了 `compareWith` 时它会分辨 `.csv` 与 `.xlsx`，并**分别说明表头在第几行**：
**CSV 的第 1 行就是表头，模板的是第 3 行** —— 「同一个问题在两处答案不同，必须知道自己在读哪一个」。
导出件里若还留着模板的注释行（`注意事项` / `导入分镜表前请删除此行`），它报 `✗`，并说明
**平台会在导入时失败，而本地任何断言都不会红**。它末尾也声明：**不证明平台会接受**这份导出件。

**`duanju_recall`** — 六节：系列级声明（`story.json`）→ 生成参数（`manifest.json`，含 `measuredCredits` 与
`unmeasured` 条数）→ 圣经（四件的条数、id 前缀、道具是否缺 `allowedActions`、场景是否缺 `space`）
→ 分镜表（张数、镜头总数、表头与权威 28 列是否逐字一致）→ 正文导入件（整部件的字节数、**非空白字数**、
分集标记用到的字、是否混用、是否超 10 万字；单集件份数）→ 平台读数（自洽性）。
每一节都区分「读到了」与「读不到」，末尾重印：**「读不到一律不等于通过。下一步该做什么由你决定，不由这份投影决定。」**

**`duanju_checkpoint`** — 写入报告，四行：目标路径与动作（`replaced` / `appended` / `created`）、
**`标记外字节：逐字节保全`**（或一个红色告警）、字节数前后对比。
标记不成对时它**拒绝写入**并说明原因，文件**一个字节都没动**。
`dryRun: true` 时它把将要落入区块的正文原样打印出来，**不写任何字节**。

## 五、四个反复咬人的读数陷阱

1. **列数不要从任何文档里引用。** 权威是 `script-gate.mjs` 的 `REQUIRED_COLUMNS` 数组字面量（**28** 列，`:87-118`）。
   同一个文件里**三处说法不一致**：文件头 `:29` 写「吃 20 列」、`:34-35` 的自我订正也写 20、HELP `:443` 打印「25 列表头」。
   用 `duanju_contract`，它机械抽取并**列出所有与数组不符的说法**。
2. **`findings` 是列表。** 见第二节。
3. **没出现的 code 不是通过。** 见第二节。
4. **`UNAVAILABLE` / `CRASHED` 不许折叠进 `PASS`。** 引用闸门报告时，把那两句「不许折叠的读法」一起带上。

## 六、工具本身的可信边界（写下来，免得当成绝对权威）

- `duanju_gate` 的结论**全部来自闸门**。工具自己的判断只有两个：分类成哪一态、以及渲染。所以它的可信度
  **等于 `script-gate.mjs` 的可信度**，不多也不少；闸门漏判的，工具同样漏判。
- `duanju_contract` / `duanju_template` 会给出模板文件的 **sha256**。**不一致就说明模板文件被换过**，
  那时基线的列数不再适用 —— 先看文件，再用基线。
- `duanju_recall` 的读数自洽性**只校验自洽**：它抓转述错字与「等级与总分映射不符」，**抓不出整份报告读错**。
  这句话每次都印在它的输出里，引用读数时也带上。
- **工具报不出来，可能是能力问题，不是通过。** 脚本不存在时 `duanju_gate` 返回 `CRASHED` 并写明
  「找不到闸门脚本：<路径>」；模板目录被移动时 `duanju_template` 说「**这不是通过，是判不了**」。
  这两句是设计，不是兜底话术。
