# 工序与交付契约

## 一、这条流水线被一道闸门切成两段

```
① 编剧（智能体）        products\<剧名>\script\可导入-<剧名>-全N集.txt
        ↓
② 平台评估（用户做）     有戏AI：登录 → 粘贴剧本 → 生成剧集 → 立即发起评估
        ↓
③ 读数回填（智能体）     products\<剧名>\评估报告-回填.json 的 readings[]
        ↓
④ 用户说「满意」
        ↓
⑤ 分镜表（智能体）       28 列 CSV → 平台可导入的 xlsx
        ↓
⑥ 出片与投稿（用户在平台上做）
```

**②④ 是硬闸门，不是复核。** 这条流水线的两次「停下来等人」都由用户执行、用户判断。
你在 ① 之后结束回合；你在 ③ 之后再次结束回合，直到用户说满意。

> **绝不在用户说满意之前写分镜表。** 本地闸门的 `PASS` 是**手艺**判据，平台的评级是**内容**判决。
> 本项目已经为此付过学费：一份**本地断言全绿**的剧本，平台判了 **D 55.7**（D-17/D-18）。
> 「本地过了」不是「可以继续」的理由。

## 二、① 编剧阶段：交付什么，交付成什么样

**交付物**：`products\<剧名>\script\可导入-<剧名>-全N集.txt` —— **平台真正导入的那一份**。
（同目录还有 `单集` 版，那是写分镜时的依据，不是交付物。）

由 `tools\episode-build.mjs` 从「一份紧凑 JSON 源」生成，**不要手写这个 txt**：

```powershell
node D:\AIVideo\tools\episode-build.mjs --series D:\AIVideo\products\<剧名> --all --script
```

### 四条会决定评级/被拒的硬约束

| 约束 | 值 | 谁判 |
| --- | --- | --- |
| **单集字数** | 目标 **1 600–1 900**；平台硬上限 **2 000** | E9（本地）＋平台（超了直接拒） |
| **全集字数** | ≤ **100 000** | 平台（「剧本支持10万字以内」） |
| **分集标记** | 全用 `第N集`，或全用 `第N章`；**不得混用** | E9（本地）＋平台（混用即分不了集） |
| **首集编号** | 从 1 开始、连续 | E9 |

> **字数是内容判据，不是格式判据。** 本项目的实测：全 12 集 **2 526 字**（每集约 210 字）→ **D 55.7**；
> 同一故事改写后全 12 集 **20 554 字**（每集 1 630–1 895 字）→ **A 82.6**，五维全部上升。
> 「薄」在这里不是风格问题，是**扣分项**。写完必须**读回文件数出真实字数**，不是估计。

平台原文（两条真的会拦你的规则，其余都是我们自己的纪律）：

> 请导入剧本，将为你自动分集（文本请用"第n章/集"分割）
> **不能混合使用**，比如在同一个剧本中，同时使用：第1章， 第2集 ，这样是不能分集的

## 三、闸门的三种结论与退出码（**本工作台最重要的一条设计**）

```powershell
node D:\AIVideo\tools\script-gate.mjs --series D:\AIVideo\products\<剧名> --episode <N>
node D:\AIVideo\tools\script-gate.mjs --series D:\AIVideo\products\<剧名> --episode <N> --format json
node D:\AIVideo\tools\script-gate.mjs --series D:\AIVideo\products\<剧名> --series-check      # 系列级：E19 发布门槛
node D:\AIVideo\tools\script-gate.mjs --series D:\AIVideo\products\<剧名> --cross-episode     # 跨集：E21–E29
```

| 结论 | 含义 |
| --- | --- |
| `PASS` | 判完了，通过 |
| `FAIL` | 判完了，确认不通过 |
| **`UNAVAILABLE`** | **判不了**（缺文件/缺目录/依赖缺失）—— **不是通过** |

**退出码**：`0` 全通过 / `1` 用法或输入错 / `2` 有 `FAIL` / `3` 有 `UNAVAILABLE`。
**没有 `4`。** `script-gate.mjs:45` 与 `:439` 的头注释都声称有「运行期异常」= 4，但那个文件里
**没有任何一条路径会发出它**（`process.exit(` 一次都不出现；只有 `:2853 process.exitCode = main()`，
而 `main()` 只返回 `0/1/2/3`）。运行期异常直接冒泡，Node 给的是 **`1`** —— 所以看到 `1` 时，
先分清是**参数用错**还是**脚本崩了**，这两件事在读数上长得一样。

> **`UNAVAILABLE` 绝不折叠成 `PASS`。** 本工作台付过这条学费：**「读不到」必须在输出上与「没有问题」不同**，
> 否则下游会把空结果集当成通过。工具自己会在报告末尾打印一句
> 「上面标 ? 的是「跑不了」，不是「通过」」—— 引用报告时把那句一起带上。

**看三件事，不是看退出码**：① 有没有 `FAIL`；② 有没有 `UNAVAILABLE`（逐条处理，缺素材就补素材，不许当绿灯跳过）；③ **报价数字**（那是**上限报价，不是净消费**，需用户批准）。

## 四、判据分两层，不要混为一谈

| 层 | 判什么 | 谁判 |
| --- | --- | --- |
| **单集** `E1–E20` | 这一集本身对不对：列契约、镜头标识、时长与单价、词表、角色/道具自洽、对白、`@[X]` 可解析、参考图、导入版格式、叙事结构组 | `--episode` |
| **跨集** `E21–E29` | 任何一集单独看都判不了的条件：变化链是否被下一集继承、情节锚点是否保留、重复是否被压缩、P2 结构 | `--cross-episode` |
| **系列级** `E19` | 发布门槛里本地可查的那几条（集数 ≥10 等） | `--series-check` |
| **读数自洽** `E19b` | 回填的评估读数自洽（等级是否等于映射表、五维均分×10 是否与总分相符） | 与 E19 同轮 |

`E19b` **不预测评级** —— 它只校验转述有没有抄错。

## 五、③ 读数回来之后：四件事

1. **追加**一条到 `products\<剧名>\评估报告-回填.json` 的 `readings[]`（**不改旧条目**），
   并把顶层的便捷副本同步成最新那次。
2. 跑 `E19b`，把它的结论写出来。
3. **报出与上一次读数的差**（每一项维度的升降）。
4. **标注证据等级**：读数来自用户在会话里的**转述**，本机没有该平台的登录态。
   `E19b` **抓的是转述错字，抓不出整份报告读错**。写「本次读数为用户转述」，
   能拿到导出件或截图时补进 `_原报告来源`。

**不允许**：预测评级；把本地闸门的 `PASS` 当成用户的「满意」；
平台只给分不给诊断时自己编一份诊断（如实说「这一次没有诊断文字，所以『还差在哪』没有权威答案」）。

## 六、⑤ 分镜阶段与 ⑥ 出片

分镜表用 `shotlist` 技能（28 列，权威是 `script-gate.mjs` 的 `REQUIRED_COLUMNS`），
导出用 `board-to-xlsx.mjs`，两者的调用契约见 `drama-workspace` 技能。

**⑥ 是用户在平台上做的**：生成故事板/生成剧集、投稿。你没有这个能力，也不要声称有 ——
理由与逐条步骤见 `youxi-platform` 技能。

## 七、三条已实测的失败模式，不要重犯

1. **薄**：正文写成每集两百字，结构断言全绿，平台判 D。字数是内容判据。
2. **两个真相**：改了正文忘了改分镜表（或反过来）。两者必须**同源**（都由 `episode-build.mjs` 从那份 JSON 生成）。
3. **把「跑不了」当「通过」**：闸门报 `UNAVAILABLE` 时跳过，然后在平台侧付学费。

## 八、开工前的一分钟自检

- [ ] 我知道这一步的**交付物**是哪个绝对路径的文件
- [ ] 我知道这一步**要不要过平台那道闸门**（要过 → 我交付完就停，不要顺手写下一阶段的东西）
- [ ] 我读过 `bible\*.json`，不是凭记忆写角色/道具名
- [ ] 我跑过闸门，并**引用了它的原文**（含 `UNAVAILABLE` 行与「跑不了 ≠ 通过」那句）
- [ ] 我报的每个数字都有出处；没有实测数字的地方我说「未测量」
