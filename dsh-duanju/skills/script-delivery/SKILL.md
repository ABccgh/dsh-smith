> **它们都不是剧本。**

盘上**唯一完整的一部剧**是测试夹具 `D:\AIVideo\tools\_fixtures\series-min\`（12 集、28 列分镜表、4 件圣经）。
它的用途是**回归测试**，不是内容。

⚠️ **任何技能、任何记忆层里把这三个名字当成在拍的项目，都是过期信息**，读到就当缺陷报出来。
本技能描述的是**一部新剧**要走的工序。

## 一、这条流水线被两道人工闸门切成三段

```
① 编剧（智能体）        products\<剧名>\script\可导入-<剧名>-全N集.txt
        ↓
② 平台评估（用户做）     有戏AI：登录 → 粘贴剧本 → 生成剧集 → 立即发起评估
        ↓
③ 读数回填（智能体）     products\<剧名>\评估报告-回填.json 的 readings[]
        ↓
④ 用户说「满意」
        ↓
⑤ 分镜表（智能体）       28 列 CSV → 平台可导入的 xlsx
        ↓
⑥ 出片与投稿（用户在平台上做）
```

**②④ 是硬闸门，不是复核。** 两次「停下来等人」都由用户执行、用户判断，
而且**平台的这两步你驱动不了** —— 有戏AI 没有 CLI、没有公开 API，`D:\AIVideo` 里也没有任何凭证
（实测：全树递归搜 `.env*` / `*token*` / `*cookie*` / `*credential*` / `*secret*` → **0 个文件**）。
逐条能力边界见 `youxi-platform` 技能。

### 你的回合在哪里结束（这张表是本技能的核心）

| 工序 | 谁做 | 你的回合 |
| --- | --- | --- |
| ① 写正文并交付 `可导入-<剧名>-全N集.txt` | 你 | **交付完就结束回合** |
| ② 平台评估 | **用户** | 等 |
| ③ 读数回填 | 你 | **回填完再结束一次回合** |
| ④ 说「满意」 | **用户** | 等 |
| ⑤ 分镜表 | 你 | ④ 之后才开工 |
| ⑥ 出片与投稿 | **用户** | 你没有这个能力 |

**交付之后不要再顺手写下一阶段的东西。** 结束回合时把三件事说清：

1. **你交付了什么** —— 绝对路径、字数读数、分集标记样式、你跑过的闸门结论。
2. **用户要做什么** —— 登录有戏AI → 粘贴正文 → 生成剧集 → 点「立即发起评估」。
3. **你在等什么** —— 一份评估读数（总分、等级、五维分、诊断文字，有诊断就带上）。

**等待不要用一轮轮追问占住会话**：把这件事放进用户的**持久待办**（`inbox_add`），
它会跨会话留着，用户有空时再答。会话里追着问，代价是你每一轮都在重放等待。

> **绝不在用户说满意之前写分镜表。** 本地闸门的 `PASS` 是**手艺**判据，平台的评级是**内容**判决。
> 本项目已经为此付过学费：一份**本地断言全绿**的剧本，平台判了 **D 55.7**（D-17/D-18）。
> 「本地过了」不是「可以继续」的理由。

## 二、① 编剧阶段：交付什么，交付成什么样

**交付物**：`products\<剧名>\script\可导入-<剧名>-全N集.txt` —— **平台真正导入的那一份**。
（同目录还有 `单集` 版，那是写分镜时的依据，不是交付物。）

由 `tools\episode-build.mjs` 从「一份紧凑 JSON 源」生成，**不要手写这个 txt**：

```powershell
node D:\AIVideo\tools\episode-build.mjs --series D:\AIVideo\products\<剧名> --all --script
```

### 四条会决定评级/被拒的硬约束

| 约束 | 值 | 谁判 |
| --- | --- | --- |
| **单集字数** | 目标 **1 600–1 900**；平台硬上限 **2 000** | E9（本地）＋平台（超了直接拒） |
| **全集字数** | ≤ **100 000** | 平台（「剧本支持10万字以内」） |
| **分集标记** | 全用 `第N集`，或全用 `第N章`；**不得混用** | E9（本地）＋平台（混用即分不了集） |
| **首集编号** | 从 1 开始、连续 | E9 |

> **字数是内容判据，不是格式判据。** 本文件记录的那两次实测读数：全 12 集 **2 526 字**（每集约 210 字）→ **D 55.7**；
> 同一故事改写后全 12 集 **20 554 字**（每集 1 630–1 895 字）→ **A 82.6**，五维全部上升。
> 「薄」在这里不是风格问题，是**扣分项**。写完必须**读回文件数出真实字数**，不是估计。

平台原文（两条真的会拦你的规则，其余都是我们自己的纪律）：

> 请导入剧本，将为你自动分集（文本请用"第n章/集"分割）
> **不能混合使用**，比如在同一个剧本中，同时使用：第1章， 第2集 ，这样是不能分集的

## 三、闸门：**四态**，不是三态

**首选路径是 `duanju_gate` 工具，不是手敲 node。** 参数与输出形状见第六节。

```text
duanju_gate { series: "D:\AIVideo\products\<剧名>", range: "episode", episode: 3 }
duanju_gate { series: "…", range: "series" }          # 系列级 E19
duanju_gate { series: "…", range: "cross-episode" }   # 跨集 E21–E29
duanju_gate { series: "…", range: "script-only" }     # 只跑正文
```

回退（工具不可用时）：`node D:\AIVideo\tools\script-gate.mjs --series <剧目录> --episode <N> --format json`。

| 结论 | 含义 | 是不是通过 |
| --- | --- | --- |
| `PASS` | 判完了，通过 | **是** |
| `FAIL` | 判完了，确认不通过 | 否 |
| **`UNAVAILABLE`** | **判不了**（缺文件 / 缺目录 / 依赖缺失） | **不是** |
| **`CRASHED`** | **脚本崩了**，或参数用错（`USAGE` 变体同版式） | **不是** |

### 为什么会有第四态：退出码 `4` 不可达，而且崩溃与用法错都是 `1`

闸门自己的文档写着「退出码 `0` 全通过 / `1` 用法或输入错 / `2` 有 `FAIL` / `3` 有 `UNAVAILABLE` /
`4` 运行期异常」（`script-gate.mjs:45` 与 HELP `:441`），**而 `4` 在代码里不可达** ——
全 2 859 行没有 `process.exit(4)`、没有 `return 4`：

- `main()` 定义在 `:1719`，只返回 `0/1/2/3`：`:1730` 帮助→0，`:1726` `:1734` `:1745` 用法/输入错→1，
  `:2850` 有 `FAIL`→2，`:2851` 有 `UNAVAILABLE`→3，`:2852` →0。
- 唯一的 `try/catch` 包的是 `parseArgs`（`:1721-1727`），所以**任何别的抛出都是未捕获异常**，Node 给 **`1`**。

⇒ **崩溃与用法错误在退出码上是同一个数。** 这正是 `duanju_gate` 加第四态的理由：
它**不读退出码下结论**，判据是 **stdout 能不能解析成 JSON**，加上 **stderr 里有没有「用法错误」**
（`D:\dsh-duanju-script\lib\rules.mjs:54` `classifyGateRun`；文本方言那一支见 `:121-126`）。
看到 `1` 时先分清是**参数用错**还是**脚本崩了**，不要用退出码下结论。

> **这条引用要现读。** 旧版本的本文件把 `process.exitCode = main()` 记在 `:2853`，**今天它在 `:2859`**
> （文件共 2 859 行）—— 文件长长了，没有任何检查因此变红。引用行号时先确认它还在那儿。

### 看三件事，不是看退出码

① 有没有 `FAIL`；② 有没有 `UNAVAILABLE`／`CRASHED`（逐条处理，缺素材就补素材，**不许当绿灯跳过**）；
③ **报价数字**（那是**上限报价，不是净消费**，需用户批准）。

**两条必须原样带上的话** —— 工具每次都会印（`rules.mjs:203-204`）：

> 上面标 `?` 的是**跑不了**，不是**通过**。
> 某个 code 没出现在上面，**不等于它过了**：`E5`/`E6` 在圣经读不到时会**故意什么都不发**，由 `E0-输入完整性` 代言。

**`findings` 是 list，不是 map。** `E24` 最多出现 3 次、`E11` 有 8 个发射点、`E9`/`E9a`/`E9b` 可为同一原因同时出现。
**按 code 取首条会静默丢掉结论** —— 按出现顺序整体读。

> **没出现的 code，不等于它过了。** `E5`/`E6` 在圣经读不到时会**故意什么都不发**，由 `E0-输入完整性` 代言。
> 所以「我在报告里没看到 `E6`」**不构成任何结论** —— 空白要被读成空白，不是读成绿灯。
> 想知道 `E6` 到底过没过，要么让它出现，要么去读 `E0-输入完整性` 说了什么。

> **绝不要把 `duanju_gate` 报成「闸门过了」，当它返回的是 `UNAVAILABLE` 或 `CRASHED`。**
> 本工作台为这条付过学费：**「读不到」必须在输出上与「没有问题」不同**，否则下游会把空结果集当成通过。

## 四、判据分两层，不要混为一谈

| 层 | 判什么 | 范围 |
| --- | --- | --- |
| **单集** `E1–E20` | 这一集本身对不对：列契约、镜头标识、时长与单价、词表、角色/道具自洽、对白、`@[X]` 可解析、参考图、导入版格式、叙事结构组 | `range: "episode"` |
| **跨集** `E21–E29` | 任何一集单独看都判不了的条件：变化链是否被下一集继承、情节锚点是否保留、重复是否被压缩、P2 结构 | `range: "cross-episode"` |
| **系列级** `E19` | 发布门槛里本地可查的那几条（集数 ≥10 等） | `range: "series"` |
| **读数自洽** `E19b` | 回填的评估读数自洽（等级是否等于映射表、五维均分×10 是否与总分相符） | 与系列级同轮 |

`E19b` **不预测评级** —— 它只校验转述有没有抄错。这一条要跟着读数一起出现。

## 五、③ 读数回来之后：四件事

1. **追加**一条到 `products\<剧名>\评估报告-回填.json` 的 `readings[]`（**不改旧条目**），
   并把顶层的便捷副本同步成最新那次。
2. 跑**系列级范围**的闸门（它带上 `E19b`），把自洽结论写出来。
   **追加后再跑** —— 先跑会让 `E19b` 判的是上一次的状态，那次结论是假的。
3. **报出与上一次读数的差**（每一项维度的升降，以及总分与等级的移动）。没有上一次就写「这是首次读数」。
4. **标注证据等级**：读数来自用户在会话里的**转述**，本机没有该平台的登录态 ——
   读不到报告文件，也读不到截图。写「本次读数为用户转述」，能拿到导出件或截图时补进 `_原报告来源`。

> `E19b` **抓的是转述错字，抓不出整份报告读错**。这句话要跟着读数一起出现，别让它看起来像一次实测。

**平台不会自动重评。** 用户说「不满意」时：**只改正文**，然后**明确提醒用户再点一次评估** ——
改完不点，读数永远停在旧的那次，而你以为流程在往前走。

**不允许**：

- **预测评级。**
- 把本地闸门的 `PASS` 当成用户的「满意」。
- 平台只给分不给诊断时自己编一份诊断 —— 如实说「这一次没有诊断文字，所以『还差在哪』没有权威答案」。

## 六、工具给交付契约的三件事（首选路径）

`duanju_gate` / `duanju_recall` / `duanju_checkpoint` 由宿主平面的 `dsh-duanju-script` 插件注册，
**每个会话都能看见**。**`duanju_*` 工具是首选，`node` 脚本是回退。**

| 工具 | 在交付契约里的位置 |
| --- | --- |
| **`duanju_recall`** | **声称任何状态之前先跑它。** 它做的是只读投影：`story.json` 的集数与时长、`manifest.json` 的平台模式、圣经四件、`storyboards\` 计数与列契约、`script\` 命名与字数、最新一次读数**带差值**。它的读数是**自洽性**检查，且它**每次都印那句警告**：抓得出转写错误，**抓不出整份报告读错**。 |
| **`duanju_checkpoint`** | 把投影渲染进 `products\<剧名>\项目总览.md` 的**受管区块**。**先跑 `dryRun: true`** 看它要写什么；不带 `dryRun` 就是一次写。受管区块的纪律（只改两个标记之间的字节）见 `drama-project-memory` 技能。 |
| **`duanju_gate`** | 判据本身（第三节）。**四态，不看退出码。** |

另三个（`duanju_contract` / `duanju_board` / `duanju_template`）属于分镜阶段，见 `shotlist` 技能。

> **精确参数、输出形状与四态语义，见 `script-tools` 技能**（第六节那张表只讲交付契约要用的三个）。
> 一条边界值得在这里先记住：**六个工具里没有任何一条检查被重新实现** ——
> `duanju_gate` 全部结论来自闸门，它自己的判断只有「分类成哪一态」和「渲染」。
> 所以**工具的可信度等于 `script-gate.mjs` 的可信度**，闸门漏判的它同样漏判。

## 七、⑤ 分镜阶段与 ⑥ 出片

分镜表用 `shotlist` 技能（28 列，权威是 `script-gate.mjs` 的 `REQUIRED_COLUMNS` —— **引用列数就去读那个数组，不要从文档里抄**），
导出用 `board-to-xlsx.mjs`，两者的调用契约见 `drama-workspace` 技能。

**⑥ 是用户在平台上做的**：生成故事板/生成剧集、投稿。你没有这个能力，也不要声称有。

## 八、三条已实测的失败模式，不要重犯

1. **薄**：正文写成每集两百字，结构断言全绿，平台判 D。字数是内容判据。
2. **两个真相**：改了正文忘了改分镜表（或反过来）。两者必须**同源**（都由 `episode-build.mjs` 从那份 JSON 生成）。
3. **把「跑不了」当「通过」**：闸门报 `UNAVAILABLE`（或 `CRASHED`）时跳过，然后在平台侧付学费。

> 第 3 条的变体值得单独记住：**把 `1` 读成「参数用错」而其实是崩溃**（或反过来）。
> 退出码分不开这两件事，所以**先看 stdout 是不是 JSON**。

## 九、开工前的一分钟自检

- [ ] 我知道这一步的**交付物**是哪个绝对路径的文件
- [ ] 我知道这一步**要不要过人工闸门**（要过 → 我交付完就停，**不顺手写下一阶段的东西**）
- [ ] 我把「等用户读数」放进了 `inbox_add`，而不是用追问占住会话
- [ ] 我跑过 `duanju_gate`，并**引用了它的原文**（含 `UNAVAILABLE` 行与「跑不了 ≠ 通过」那句）
- [ ] 我读的是 `findings` **整个列表**，不是每个 code 的首条
- [ ] 我读过 `bible\*.json`，不是凭记忆写角色/道具名
- [ ] 回填读数时我是**追加**的，跑自洽检查在追加**之后**
- [ ] 我报的每个数字都有出处；没有实测数字的地方我说「未测量」
